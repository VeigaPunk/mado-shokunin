| Seventy-one names, one forwarder, two tables. | 1. **Seventy-one names, one forwarder, two tables.** The keybind manager's constructor fills its table from a brace list running from `{`exec`,` (Hyprland-KeybindManager.cpp:42) to `releaseinputcapture` (Hyprland-KeybindManager.cpp:112), giving all 71 names the same closure: `m_dispatchers[name] = [n = std::string(name)](std::string args) -> SDispatchResult { return Config::Legacy::translator()->run(n, args); };` (Hyprland-KeybindManager.cpp:113). The member is a string-keyed function table and nothing else `std::unordered_map<std::string, std::function<SDispatchResult(std::string)>> m_dispatchers;` (Hyprland-KeybindManager.hpp:137). Behind it the translator holds a second table, also 71 entries and also a name-to-function map `std::unordered_map<std::string, std::function<SDispatchResult(const std::string&)>> m_dispMap;` (Hyprland-legacy-DispatcherTranslator.hpp:19), filled at Hyprland-legacy-DispatcherTranslator.cpp:797-867; its entry point refuses an unknown name before calling anything `if (!m_dispMap.contains(d))` / `Bad dispatcher` (Hyprland-legacy-DispatcherTranslator.cpp:31-32) and otherwise calls the mapped function (Hyprland-legacy-DispatcherTranslator.cpp:34). | What the bind line leaves behind. | 2. **What the bind line leaves behind.** The dispatcher word is taken by position `auto HANDLER = ARGS[2 + DESCR_OFFSET + DEVICE_OFFSET];` (Hyprland-legacy-ConfigManager.cpp:1584), and everything after it becomes the stored argument in one piece `const auto COMMAND = mouse ? HANDLER : ARGS[3 + DESCR_OFFSET + DEVICE_OFFSET];` (Hyprland-legacy-ConfigManager.cpp:1586) - no comma is touched again at this point. With the `m` flag the word is replaced by the literal and the written word moves into the argument `HANDLER = "mouse";` (Hyprland-legacy-ConfigManager.cpp:1589). The name is folded to lower case in place before use `std::ranges::transform(HANDLER, HANDLER.begin(), ::tolower);` (Hyprland-legacy-ConfigManager.cpp:1592) - so `EXEC` and `exec` are one dispatcher while the argument keeps its bytes - and it is checked against the very table a press will consult `const auto DISPATCHER = g_pKeybindManager->m_dispatchers.find(HANDLER);` (Hyprland-legacy-ConfigManager.cpp:1594). A miss rejects the line, naming the word in the message (Hyprland-legacy-ConfigManager.cpp:1598); the accepted pair is stored on the bind as `handler` and `arg` (Hyprland-legacy-ConfigManager.cpp:1624-1631), beside the submap it was written under (Hyprland-legacy-ConfigManager.cpp:1633). A dispatcher name is thus a config-time commitment: an unknown one never reaches a key press. |
| Three places call the table. | 3. **Three places call the table.** The press path dispatches collected hits from a second loop whose lookup rewrites the name for mouse binds `const auto DISPATCHER = m_dispatchers.find(k->mouse ? "mouse" : k->handler);` (Hyprland-KeybindManager.cpp:785) - which is why an `m`-flag bind reports `mouse` in `hyprctl binds` - and a miss there is only a log line `Invalid handler in a keybind!` (Hyprland-KeybindManager.cpp:799), because step 2 already refused it. Two timer callbacks bypass the press path and call the closure with the stored string: the long-press timer `DISPATCHER->second(m_lastLongPressKeybind->arg);` (Hyprland-KeybindManager.cpp:131) and the repeat timer `DISPATCHER->second(k->arg);` (Hyprland-KeybindManager.cpp:154). Neither writes the press field of step 4, whose value there is the cleared sentinel; `[INF]` a repeated or long-held `pass` bind therefore replays both key edges rather than the edge that fired. |
| What the callable receives. | 4. **What the callable receives.** Two things, and one of them is process-wide state. Before the call the press edge is written into it `Config::Actions::state()->m_passPressed = sc<int>(pressed);` (Hyprland-KeybindManager.cpp:804); after the call it is cleared `Config::Actions::state()->m_passPressed = -1;` (Hyprland-KeybindManager.cpp:814); the declared meaning is three-valued `int m_passPressed = -1; // -1 = dynamic (press+release), 0 = released, 1 = pressed` (Hyprland-ConfigActions.hpp:114). The argument arrives exactly as stored `res = DISPATCHER->second(k->arg);` (Hyprland-KeybindManager.cpp:812), with one textual exception: the mouse handler gets a one-character edge prefix glued in front `res = DISPATCHER->second((pressed ? "1" : "0") + k->arg);` (Hyprland-KeybindManager.cpp:810) and strips it on arrival (Hyprland-legacy-DispatcherTranslator.cpp:676). The return value has three fields with forgiving defaults `bool passEvent = false;` / `bool success = true;` / `std::string error;` (Hyprland-SharedDefs.hpp:53-55), so a dispatcher that returns nothing counts as a success that does not swallow the event - the deprecated `setignoregrouplock` returns exactly nothing (Hyprland-legacy-DispatcherTranslator.cpp:861). The press path folds that into its own count `res.passEvent /= !found;` (Hyprland-KeybindManager.cpp:842), and an inhibitor may still turn the result into a failure (Hyprland-KeybindManager.cpp:845-851). |
| `submap`: captured when written, written when dispatched. | 5. **`submap`: captured when written, written when dispatched.** A bind carries the submap that was current when its line was parsed (Hyprland-legacy-ConfigManager.cpp:1633, from the keyword write at :1797-1798), and a press copies the live value into the event `.submapAtPress = getCurrentSubmap()` (Hyprland-KeybindManager.cpp:396); `getCurrentSubmap` is a pure read of one string `return SSubmap{.name = Config::Actions::state()->m_currentSubmap};` (Hyprland-KeybindManager.cpp:599), whose members default empty (Hyprland-KeybindManager.hpp:25-26). The gate compares those two names with the same universal escape the modifier mask has `((k->submap.name != key.submapAtPress.name) && !k->submapUniversal)` (Hyprland-KeybindManager.cpp:652). At dispatch time the only writer is the `submap` action: the reset and empty forms write empty `Config::Actions::state()->m_currentSubmap = "";` (Hyprland-ConfigActions.cpp:1666), and a named form is written only after a scan of the bind list finds a bind carrying it `Config::Actions::state()->m_currentSubmap = submap;` (Hyprland-ConfigActions.cpp:1674), otherwise the call fails and says why `Cannot set submap` (Hyprland-ConfigActions.cpp:1681). A submap therefore exists because some bind named it: switching to any other name is an error string, not a state change. Two ordering rules ride on this dispatcher - it marks the event consumed and breaks, once while hits are still being collected (Hyprland-KeybindManager.cpp:775-778) and once after the call (Hyprland-KeybindManager.cpp:816-819), so it is dispatched alone; and a bind whose submap carries a reset target switches after its own dispatcher returns, but only if that dispatcher left the name untouched `if (k->handler != "submap" && !k->submap.reset.empty()) {` / `if (submapBefore == submapAfter)` / `Config::Actions::setSubmap(k->submap.reset);` (Hyprland-KeybindManager.cpp:820-823). |
| `pass`: the handler that presses the key again elsewhere. | 6. **`pass`: the handler that presses the key again elsewhere.** `ActionResult Actions::pass(std::optional<PHLWINDOW> w)` (Hyprland-ConfigActions.cpp:1465) resolves its argument as a window selector, points keyboard focus - or pointer focus when the last event was a button - at that window, re-sends the modifier state, then replays the code recorded on the event (Hyprland-KeybindManager.cpp:386) as press only, release only, or both, chosen by the three-valued field of step 4: `if (S.m_passPressed == 1) {` (Hyprland-ConfigActions.cpp:1487), `} else if (S.m_passPressed == 0) {` (Hyprland-ConfigActions.cpp:1492), and a branch that sends both edges in one call (Hyprland-ConfigActions.cpp:1499-1500). `pass` is one of the five names the press path handles specially `const bool SPECIALDISPATCHER = k->handler == "global" // k->handler == "pass" // k->handler == "sendshortcut" // k->handler == "mouse" // k->releasePending;` (Hyprland-KeybindManager.cpp:782); a pressed one is remembered `m_pressedSpecialBinds.emplace_back(k);` (Hyprland-KeybindManager.cpp:795) and forgotten on its release (Hyprland-KeybindManager.cpp:793). The same field is the other two special handlers' input: `global` forwards it to the client (Hyprland-ConfigActions.cpp:1634), and `mouse` reads it as its only notion of pressed `const bool PRESSED = Config::Actions::state()->m_passPressed == 1;` (Hyprland-ConfigActions.cpp:1640), degrading to `MBIND_INVALID` otherwise (Hyprland-ConfigActions.cpp:1643). `sendkeystate` is the one dispatcher that writes the field itself, saving and restoring it around its work (Hyprland-ConfigActions.cpp:1603-1615). |
| No shared grammar: each dispatcher reads the tail its own wa | 7. **No shared grammar: each dispatcher reads the tail its own way.** Nothing re-tokenises `k->arg` between steps 2 and 4; the split happens inside whichever implementation the name selected, and the pinned table shows at least four different readings. `sendshortcut` demands exactly three comma-separated fields and rejects anything else `CVarList2 ARGS(args, 3);` / `if (ARGS.size() != 3)` (Hyprland-legacy-DispatcherTranslator.cpp:532-535), so a fourth comma in its tail is a config-time error rather than part of the argument. `setprop` takes three space-separated fields and rejoins what follows `CVarList2 vars(args, 3, ' ');` (Hyprland-legacy-DispatcherTranslator.cpp:773). `alterzorder` cuts once at the first comma (Hyprland-legacy-DispatcherTranslator.cpp:684). `mouse` strips exactly one character (Hyprland-legacy-DispatcherTranslator.cpp:676). `exec` does not split at all and hands the tail to the process executor (Hyprland-legacy-DispatcherTranslator.cpp:48-51). The contrast with the bind line is the point: there the field count is fixed by the parser and the final field keeps its commas (held, `bind-table-r25.md:38` and `keybind-rule-semantics.md:73`), so `exec` receives `foo, bar` intact while `sendshortcut` receiving the same shape would refuse it. An argument's grammar is a property of one dispatcher, and a claim about "the" argument grammar would be false against these pins. |
| The socket verb is the same table behind a different front d | 8. **The socket verb is the same table behind a different front door.** One registered request command serves it (Hyprland-HyprCtl.cpp:2036). Its body drops the command word (Hyprland-HyprCtl.cpp:1128), hands a Lua config to `eval` and returns before the table is touched (Hyprland-HyprCtl.cpp:1130-1141), and otherwise cuts the remainder at the first space only: everything before it is the name, everything after it is the argument (Hyprland-HyprCtl.cpp:1143-1147). The lookup and the call are the bind path's `m_dispatchers.find(DISPATCHSTR)` (Hyprland-HyprCtl.cpp:1149) followed by the call and a one-line reply, `ok` or the dispatcher's own error text (Hyprland-HyprCtl.cpp:1153-1157), with an unmapped name reported as `Invalid dispatcher` (Hyprland-HyprCtl.cpp:1151). Three consequences follow from the code alone. First, the argument is as raw here as it is for a bind, so the same dispatcher sees the same string through either door. Second, this path never performs the write at Hyprland-KeybindManager.cpp:804, so the field keeps its `-1` default: a `pass` issued this way always takes the both-edges branch of step 6, and a `mouse` issued this way takes the degraded branch at Hyprland-ConfigActions.cpp:1643. Third, a submap switch through the socket still has to name a submap some bind carries, by step 5's refusal. |
| Which branch this host takes. | 9. **Which branch this host takes.** The socket body tests the configured manager's type before the table (Hyprland-HyprCtl.cpp:1130), and that type is set by which config file the directory holds - the held rule is that a `hyprland.lua` selects the Lua manager and its absence leaves `hyprland.conf` in charge (`corpus/knowledge/hyprland-config-era-r12.md:41`).
