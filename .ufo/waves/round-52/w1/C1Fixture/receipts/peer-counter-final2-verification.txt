C. NEW FINDING — THE NARROWING LETS A SELF-POINTER BE LAUNDERED
----------------------------------------------------------------------
The narrowing is sound for the peer's control-G case (a row whose description names the
ledger in prose while its pointer designates an accountable document IS accounted for),
but it can be turned around. The frozen claim's target defect is a self-pointer: a row
whose accountability pointer names the ledger itself. Under the narrowing, a row escapes
self_pointer as soon as ANY accountable target appears ANYWHERE in the row — including
in a cell that is not the pointer region.

N4 — the pointer cell names BOTH the ledger and an accountable document:
  row: | `quality/counters/c1-r47-terminal.py` | PRED-C1-r47 scores the terminal resolver
       on 190 fixtures and 150 generated cases. | `quality/tool-ledger.md` and

  C1_R52: ... self_pointer=0 generic_desc=0 verdict=TARGET_MET
  exit=0        ACCEPTED

N5 — 4-cell row: cell 3 (the pointer cell) names the LEDGER, cell 4 names an accountable
     document:

N8 — the same row, but the second cell names a document that does NOT name the
     instrument, so no accountable target exists:
  row: ... | `quality/tool-ledger.md` | `README.md` |
  detail: self_pointer path=quality/counters/c1-r47-terminal.py target=quality/tool-ledger.md
  -> self_pointer=1 verdict=TARGET_MISSED, exit=1    REJECTED

Reading. N7 versus N8 isolates the mechanism exactly: the self-pointer charge depends
only on whether SOME accountable target exists anywhere in the row, not on whether the
accountability pointer itself is the ledger. A row can therefore name the ledger as its
accountability pointer and be accepted, by appending an accountable document name to the
row. That is precisely the defect class the frozen C1 claim names — "a self-pointer" —
and the counter accepts it.

This is NOT the peer's fault in the sense of a bug in what they were asked to fix; it is
a direct consequence of the narrowing they chose for control-G, which they explicitly
flagged as a judgement call with the alternative named ("the fail-closed form (any
mention of the ledger disqualifies the row), which is a one-line change back"). The
fail-closed form would reject N7/N5/N4 but would also reject control-G, the peer's
point.

The narrower fix that keeps control-G: apply the non-self scan to the POINTER REGION
only (the ledger's own cell 3 and after) and charge self_pointer when the ledger appears
there, regardless of whether another cell names an accountable target. Control-G's
accountability pointer is its cell 3, which does not name the ledger, so control-G still
passes; N4/N5/N7, whose pointer region does name the ledger, would be charged. This is
an observation for the peer and the L1, not an edit by this seat.

Note the harness does not see this: the harness's mut-selfptr fixture puts the ledger in
the pointer cell with NO other accountable target, which is N1 (rejected correctly). The
laundering needs a second cell.
