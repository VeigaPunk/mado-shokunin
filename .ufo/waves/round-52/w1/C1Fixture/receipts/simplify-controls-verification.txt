B. WHY F3-FORGED IS CAUGHT ON ONLY 10 OF 82 ROWS — THE MECHANISM
----------------------------------------------------------------------
This is the peer's disclosed ceiling, and this seat measured exactly why.

F3-forged replaces every production description with a generic filler of the shape
`Generic accountability note <N> <a few words>.`. The counter rejects a row when the
description shares NO two-word phrase with the instrument's own bytes that survives the
four filters (the instrument's own path words, the population's naming vocabulary, a
filesystem-path fragment, English function words).

The filler's trailing words are lifted from the instrument's own header, so the filler
often still shares a REAL phrase with the instrument's bytes. Worked examples, using the
counter's own normalize/bigrams/path_words/path_fragments/FUNCTION_WORDS:

  tools/mado-action-plan.py
    desc: "Generic accountability note 0 mado action plan py."
    bound bigrams in body: ['mado action', 'action plan', 'plan py']
    surviving after the four filters: []
    -> REJECTED (generic_desc=1, reason=bound-only-by-name-path-or-function-words)
    Every bound bigram is made of the instrument's own path words.

  tools/mado-anims.py
    desc: "Generic accountability note 1 static resolver for the."
    bound bigrams in body: ['static resolver', 'resolver for', 'for the']
    surviving after the four filters: ['static resolver', 'resolver for']
    -> ACCEPTED (generic_desc=0)
    "static resolver" is a genuine phrase in that instrument's own bytes, and it is not
    made of path words, not a path fragment, and not function words. So it survives.

So the count of 10 is not arbitrary: it is the number of rows whose generic filler
happens to be built ONLY from that instrument's own path words. The other 72 rows carry a
functional phrase lifted from the instrument's header — the very thing the description is
for — so the phrase test cannot tell them from an honest description.

This is the same lexical-binding ceiling this seat measured independently by replacing
each production row's description with `pred c1 does things for the widget registry`
(caught 59, accepted 23): a phrase copied out of the instrument's own bytes satisfies the
context clause. The two measurements differ in which phrase is copied, and therefore in
the split, but they are the SAME defect: the clause binds a description to the
instrument's bytes lexically, and the instrument's bytes contain the very functional
phrases an honest description would use.

----------------------------------------------------------------------
C. WHAT THIS MEANS FOR THE FROZEN CLAIM
----------------------------------------------------------------------
The frozen claim limits C1 to "bounded accountability checks, not prose entailment", so
this ceiling does not contradict the claim as frozen. It is the boundary of a lexical
clause, and the peer records it with its construction rather than claiming it closed.
For the wave-2 critic's benefit: the attack is to copy a real functional phrase out of
the instrument's own bytes into a description that says nothing about the function. The
counter cannot see that, and no purely lexical rule can, because the phrase IS the
instrument's own functional vocabulary.
