## Replay tree (the counter's own recipe, with one forced deviation)

`c1-score.sh` recipe: `git clone --shared` the lane, `checkout 579f694`, copy the draft tool to `tools/`,
copy the draft counter + warm fixture file to `quality/counters/`, commit, score `--rev HEAD`.

Deviation 1 — **sparse checkout**. A full clone checkout cannot be written under the seat's 1 MiB file cap: the lane
carries corpus files larger than 1 MiB. Observed:

```
error: unable to write file .ufo/waves/round-22/audit/fixtures/cases/AuditRawOversizedBundle/bundle.json
fatal: unable to checkout working tree
```

and the lane's own `.git/index` is 2,771,712 B, so even the index write fails:

```
fatal: sha1 file '/fast/scratch/hyaku/mado-r48/RevC1Explain/clone-reference/.git/index.lock' write error: File too large
```

Fixed with `git clone --shared --no-checkout`, `git config index.sparse true`, `git sparse-checkout init --cone`,
`git sparse-checkout set tools quality .ufo/waves/round-47/fetch`, then `checkout 579f694`. Sparse index: 16,990 B.
`git -C "$D" rev-parse --show-toplevel` was asserted equal to `$D` before every commit, as the seat requires.

Deviation 2 — **RLIMIT_FSIZE for the instrument process only**. Under the seat's `ulimit -Sf 2048` (1,048,576 B,
measured with `resource.getrlimit`), the counter itself aborts while assembling its sandbox: it copies the externals
out of `/usr/bin`, and the largest is `gawk` (1,274,872 B).

```
OSError: [Errno 27] File too large: '/usr/bin/gawk' -> '.../probe-work/bin-wqm7uvxi/awk'
```

So the counter call runs in a subshell with `ulimit -Sf 4096` (2 MiB); every file my own commands write stays under
1 MiB. Largest file produced by any run, instrument or seat: `out-cachepath.txt`, 66,794 B. Peak scratch 363 MB
(< 2 GB); deleted at the end.

Note: `ulimit -f 2048` also lowers the *hard* limit (bash sets both), which then forbids `ulimit -Sf 4096` in a child
(`cannot modify limit: Operation not permitted`). The seat's guard is therefore applied as `ulimit -Sf 2048`.
