D-2  THE ACCEPTED WORD-SIZE SET IS WRONG IN THE RECEIPT (and in the shared contract)
     Receipt S524 row label: "word size 1/2/4, swap at parse".
     The C at xdgmimemagic.c:440-443 reads
       if (matchlet->word_size != 0 &&
           matchlet->word_size != 1 &&
           matchlet->word_size != 2 &&
           matchlet->word_size != 4)
         -> parse error
     The set is {0,1,2,4}: word_size 0 IS ACCEPTED, and it is treated like 1.
     The whole swap + modulo block is guarded by xdgmimemagic.c:471
       if (matchlet->word_size > 1) { ... }
     so with word_size 0 (or 1) there is NO byte swap AND NO modulo check:
     value_length % word_size is never evaluated (for 0 that would be a division by
     zero). The receipt's own quoted rule "rejects value_length % word_size != 0"
     is therefore true only for word_size 2 and 4.
     MEASURED (oracle, r95 control, text-mode fixture):
       >0=\x00\x02AB~0    data "AB" -> text/x-ws0b    (accepted, no swap)
       >0=\x00\x03ABC~0   data "ABC" -> text/x-ws0odd  (accepted, ODD length, no modulo check)
       >0=\x00\x03ABC~2   data "ABC" -> text/plain      (rejected: 3 % 2 != 0 -> section dropped)
     IMPACT: a model that accepts only {1,2,4} would reject a legal `~0` section the
     oracle matches, and a model that applies the modulo check unconditionally would
     divide by zero. The C1 draft in build/ states the correct rule ("only 0, 1, 2, 4
     pass :440-443; the C treats 0 like 1") and agrees with the oracle on all 116
     non-cache-mode fixtures compared here, so the DRAFT is right and the RECEIPT and
     the shared contract wording ("1|2|4 only") are wrong.

The oracle is the installed glib2 2.90.1-1; it is the labelling authority.

M-1 byte swap, word size 2 (value bytes 01 02, LE host)
    >0=\x00\x02\x01\x02~2   data 02 01 -> text/x/sw     (value stored byte-swapped)
    >0=\x00\x02\x01\x02~2   data 01 02 -> octet-stream (no match: unswapped bytes)
    >0=\x00\x02\x01\x02~1   data 01 02 -> text/x/sw     (word size 1: no swap)
    CONFIRMED: 2 and 4 byte-swap the value (and the mask) per word at parse time.
    PROVENANCE (a real gap in the receipt): the swap is under `#if LITTLE_ENDIAN`
    (473, 482). LITTLE_ENDIAN is NOT defined by glib's own build: the upstream
    meson.build defines only g_byte_order/G_LITTLE_ENDIAN for the public
    glibconfig.h; gio/xdgmime/meson.build adds only -DHAVE_CONFIG_H and
    -DXDG_PREFIX. It comes from glibc's <endian.h> (bits/endian.h under __USE_MISC),
    which xdgmimemagic.c reaches through its own include set -- verified by compiling
    that include set standalone: LITTLE_ENDIAN is DEFINED. The receipt's claim "on this
    LE host 2/4 values and masks are byte-swapped" is TRUE for this host, but the
    located quote it offers (421-450) is the modulo check, not the swap, and the
    LITTLE_ENDIAN guard is not cited at all. The corpus row should cite 471-497 and
    name the guard.

M-2 accepted word sizes {0,1,2,4}; modulo check only when word_size > 1
    ~0 with even value length  -> accepted, matches
    ~0 with ODD value length    -> accepted, matches   (no modulo check, no swap)
    ~2 with odd value length    -> parse error, whole section dropped
    ~3                        -> parse error, whole section dropped
    ~5                        -> parse error, whole section dropped

M-3 cache-mode trigger is loadability, not presence
    see D-3: 0/14/39-byte and bad-version mime.cache -> TEXT mode; >=40 bytes with
    version 1.1/1.2 -> CACHE mode. Also: a valid cache in dir A makes the whole
    answer come from the cache; a text magic file in dir B is then ignored.

M-4 error recovery
    a bad matchlet line drops its whole section and the file continues;
    a bad header (no ']') also drops the section and consumes the NEXT line as well;
    a bad header followed by a junk line then a good section -> the good section
    survives (the junk line absorbs the skip).

M-5 insert / lookup order
    priorities [10 then 90] -> the 90 section wins (file order irrelevant);
    equal priorities -> the earlier section in file order wins;
    two directories, equal priority -> the earlier directory's section wins
    (one global list across directories, read in XDG_DATA_DIRS order).

M-6 tree / indent rules
    indent 0 is the top level; a first matchlet at indent 1 -> the section never
    holds; indent 0 -> indent 2 (skipping a level) -> the section never holds;
    a parent that holds with a child that does not -> the whole section fails;
    a child that holds -> the parent holds.

M-7 data path
    len 0 -> application/x-zerosize (priority 100);
    no magic match -> text/plain / octet-stream by the 128-byte fallback;
    a name type plus a sniffed type: sniffed_prio >= 80 wins outright (80 and 90
    win; 50 and 79 do not), else the first name type that is a subclass of the
    sniffed type, else the first name type, uncertain.

M-8 header gate
    a magic file whose first 12 bytes are not exactly "MIME-Magic\0\n" contributes
    no magic at all; a file shorter than 12 bytes likewise.
