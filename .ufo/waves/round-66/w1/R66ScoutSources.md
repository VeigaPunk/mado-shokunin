## 4. Does any C1 rule pretend to prove truth? — No, with two wording traps

Observed evidence: r65's own reviewer forged the register with **8 all-false state cells** and a real receipt pointer and
the r65 counter returned `TARGET_MET rc=0` (`.ufo/waves/round-65/w1/R65RevRegister/report.md` §A3; round-65 mutation
matrix confirms `neg-dupgroup` MET). The new rules close shape/pointer holes, not state truth.

- Heading uniqueness proves there is one block, **not** that it is the authoritative one: deleting the genuine block and
  inserting a forged same-headed block with 8 true-shaped rows, a resolving receipt per row, and the committed live line
  still passes.
- Per-row receipt resolution proves each row names **some** committed file under the round-65 receipts tree. It does not
  prove the receipt defines the row's probe, or that the probe ran, or that the state cell follows. A waybar row could
  point at `windows-plane-absence-r65.txt` and pass.
- The exact live line proves a committed file at `gate-live-r65.txt` contains that line at `--rev`. It does not prove a
  live gate ran in this round, that the line came from `tools/mado-verify.sh`, or that the live plane is clean now. The
  line predates this round and its banner is `mado-verify.sh v1 (mado-shokunin round 5 / M5-2)`.
- The predicate itself says “State-cell truth remains NOT measured”, so no rule **claims** truth. The traps are report
  wording: `gate=live`/`gate=ok` can be read as a current live verdict, and “resolved” can be read as “substantiated”.
  Recommend the counter print e.g. `gate=live-line-at-rev` and a `detail: state cells NOT measured` line; reports must not
  say the register/state cells were verified.
