## Findings

- **Keysym names / case:** Binds.md:36-40 says use the segment after `XKB_KEY_`. The Hyprland 0.56.2 matcher calls `xkb_keysym_from_name` both exact-case and case-insensitive, accepting either result (pinned `Hyprland-KeybindManager.cpp:710-725`). This supports the doc guidance; it does not promise case sensitivity. `keybind-rule-semantics.md`'s cited `[INF-docs]` level is superseded for this implementation by the code evidence, not contradicted by it. The wiki does not spell out the dual-lookup behavior.
- **`code:`:** Binds.md:42-49 documents `code:<keycode>` and an example. The pinned legacy parser recognizes numeric `code:` values and stores the suffix as keycode (`Hyprland-legacy-ConfigManager.cpp:1481-1489`); matcher has a keycode branch (`Hyprland-KeybindManager.cpp:696-697`). Consistent. The parser also treats bare numeric keys >9 as keycodes and `1`..`9` as names; that is an additional code fact not stated by the wiki, not a contradiction.
- **`resolve_binds_by_sym`:** Binds.md:461-474 describes first-layout behavior by default and symbol-on-current-layout behavior when enabled; Variables.md:219 describes false/true similarly and gives default `false`. Code selects `m_xkbSymState` when enabled and `m_xkbTranslationState` otherwise (`Hyprland-KeybindManager.cpp:369`); option is per-device and set from config (`Hyprland-InputManager.cpp:1224,1241`), with false default (`Hyprland-ConfigValues.cpp:278`). These agree at the user-visible level. Code details the state mechanics more precisely than docs.
- **Modifier masks:** Binds.md:82 says `ignore_mods` ignores modifiers. Code's mask gate is bypassed under `ignoreMods` (`Hyprland-KeybindManager.cpp:652`, also evidenced in entry line 68); otherwise it compares masks. No discrepancy identified in the cited wiki material. The wiki flag table does not specify the mask's internal construction/order/equality details, so it cannot serve as evidence for those finer claims.
