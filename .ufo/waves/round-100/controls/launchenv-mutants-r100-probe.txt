FINDINGS ROUTED (L1, case owner, C1 counter owner)
  1. A path:null case MUST be scored with no PATH key in the child env. Under the r99 leg's
     PATH="" env the pristine candidate answers {root}/probe where the class expects
     {root}/./probe: a counter that reuses that env scores the new class wrong (demonstrated on a
     built root with the same candidate bytes).
  2. The /usr/bin-only arm of clause 1 cannot be labelled through Exec (a spawned /bin,/usr/bin
     program writes no probe record; and Terminal=true + PATH absent starts a real terminal -
     /usr/bin/xdg-terminal-exec EXISTS on this host). The frozen file's TryExec=sh + absolute
     Exec={root}/probe.sh shape is the safe encoding; it is load-only and kills m2 at
     pd-sysbin-unset, so the separation is causal.
  3. m5 (IS_DIR half) is not covered by the new class; it lives on the r99 prog-dir cases. The
     r100 file is the whole set, so all six die - but a reader auditing "the new class alone"
     should know m5 is carried by the old cases.
  4. m6's "or the reverse" reading is not the observed oracle behaviour: two oracle runs measure
     './' preserved ({root}/./probe); a normalising candidate is the wrong direction.
  5. m3 IS covered by the new class at pd-wd-unset (Path=<root>/work, probe only in work/): the
     early working-dir join is what finds it, so the cwd pair is a non-separating control for
     unset-vs-empty yet still load-bearing for the join.
