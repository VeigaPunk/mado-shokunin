## Findings

### P2 — challenge value leaks through inherited environment reporting

- Evidence: `quality/counters/c1-r75-landing-controls.py:202-205` adds the nonce to the inherited child environment. Frozen `quality/counters/c1-r72-landing-controls.py:548-549` sends that environment to `describe_env`; its `:375-386` prints every non-PATH value verbatim. The wrapper changes `emit` prefixes (`c1-r75-landing-controls.py:199-200`) but does not replace this renderer.
- Exploit path/impact: anyone receiving a raw successor-harness receipt receives `MADO_LANDING_NONCE=<current challenge>` in `MADO_R75_CHILD_ENV`, beyond the designated witness. This is an ephemeral test challenge, NOT evidence of an exposed account credential. It violates the requested value-minimization boundary; it does not by itself prove replay can pass in a different run or that assertions are authentic.
- `MADO_R75_CHALLENGE` itself (`:227-228`) prints only source, length, generation digest and revision, NOT the nonce. The disclosure occurs later in the inherited reporting path.
- Smallest remediation: install a wrapper-local `describe_env` adapter that substitutes a redacted value for this key before calling the frozen renderer. Preserve the frozen generation bytes and fixed witness behavior; add a raw-output disclosure regression without persisting the real nonce.
- Status: static data-flow finding, not dynamically exercised. Routed privately to MadoR75.

### P2 — successor loader validates the root, not its pre-existing output descendants

- Evidence: `c1-r75-landing-controls.py:83-103` rejects symlinks in the supplied scratch root and its ancestors. `:168-169` then accepts an existing `gen-home`; `:185-189` accepts an existing `generation` directory and opens its fixed `c1-r72-landing-controls.py` pathname with ordinary `open(..., "wb")` before `runpy.run_path`.
- Exploit path/impact [INFERENCE]: a different writer with access to a reused/shared scratch tree can prepopulate `generation` or the final file as a symlink. Root validation does not inspect either descendant; the verified bytes can consequently be written outside the declared scratch. A writer racing the subsequent pathname load could replace the verified file before execution. No such symlink or race was created during this review.
- Smallest remediation: allocate a new private unpredictable work directory under the validated scratch root and place both generation and home beneath it; do not reuse attacker-prepopulatable output paths. For adversarial shared-parent guarantees, use directory-FD/no-follow operations rather than check-then-open path validation.
- Scope: this is a new surface in the standalone successor loader. The outer fixture counter normally supplies fresh per-case roots; that does not make the standalone loader safe for reused scratch. The two other new instruments clear their fixed work trees before populating them; shared-root races and concurrent runs remain outside their demonstrated protection.

### P2, conditional trust-boundary advisory — C2 executes an unpinned base generation

- Evidence: `quality/counters/c2-r75-shapes.py:1372-1383` extracts `BASE_COUNTER`, writes it, executes it with `runpy.run_path`, and only THEN prints its digest. `:1425` defaults an omitted `--base-rev` to the measured revision, and `:1446` calls this loader. No base-generation digest comparison precedes execution.
- Exploit path/impact [INFERENCE]: supplying an attacker-controlled measured repository/base revision can cause arbitrary Python execution in the counter process, not merely AST classification. Its Git subprocess environment (`:86-96`) inherits all non-GIT variables rather than the C1 child allowlist. This is not evidence of a secret printed by the frozen receipt, nor a claim that trusted pinned round-75 invocation is compromised.
- Smallest remediation: pin the intended held round-74 generation before executing it, or explicitly require trusted executable input revisions rather than representing arbitrary repositories as passive census data. The frozen measurement command already names a specific trusted base revision.
