# C1 checker design — mutation analysis

Basis: frozen controls (a) omit one population file, (b) pointer file lacks basename, (c) empty description, (d) dangling ledger row, and (e) round-base ledger absent. The claim requires population = tracked `tools/`, `quality/*.py`, `quality/counters/*.py`; exact-once rows; non-empty description; and an existing pointer file containing the corresponding basename. “Selftest catches” assumes a hermetic selftest actually runs that mutant against an asserted failing fixture and checks both status and counter/output. The claims specify hermeticity but do not enumerate selftest arms, so where no arm is stated this is not guaranteed.

| # | Mutation | Fixture/control it must FAIL against | Would specified `--selftest` catch? |
|---|---|---|---|
| 1 | Population glob omits `quality/counters/*.py`. | A: fixture with a counter script absent from ledger; must report uncovered. | Not guaranteed; only if selftest exercises each population class. Add a population-class arm. |
| 2 | Population glob is recursive for `tools/` but only accepts top-level files (or vice versa). | A: nested tracked tool file omitted from ledger. | Not guaranteed; require nested-population fixture if recursive population is intended. |
| 3 | Row parser accepts only `- `path`` without the documented separator/description fields, silently dropping malformed rows. | D: malformed row naming an out-of-population file must become dangling or parse error, never disappear. | Not guaranteed; the four data controls need not include malformed syntax. Add malformed-row arm. |
| 4 | Row parser splits on the first `|`/delimiter incorrectly, truncating filenames containing that delimiter or swallowing later columns. | A/D: fixture basename with delimiter; omission or dangling must be visible. | Not guaranteed; filename edge cases unspecified. Add delimiter-bearing filename arm or ban delimiter in grammar. |
| 5 | Basename containment checks only `basename in pointer_text` rather than reading the resolved pointer file contents. | B: pointer resolves to existing file whose contents omit basename. | Yes, if control (b) is a real file-content fixture and asserts `bad_pointer>0`; otherwise no. |
| 6 | Basename check uses substring (`mado-tool.py` matches `not-mado-tool.py`) instead of the required basename token. | B: decoy containing basename only as a longer filename substring. | Not guaranteed; ordinary missing-basename fixture catches absence, not substring false positive. Add decoy-substring arm. |
| 7 | Pointer resolution permits paths escaping repo via `../` or absolute paths. | B: pointer names an outside-repo file containing basename; must be bad pointer. | Not guaranteed by listed control if it only uses a missing in-repo path. Add traversal/absolute-path arm. |
| 8 | Duplicate ledger rows are deduplicated before accounting, so a population file listed twice still looks exact-once. | A / exact-once criterion: fixture duplicates a valid row; must MISS. | **Live mutant:** the frozen controls do not expressly include duplicate rows; a selftest built only around (a)–(e) can pass it. | 9 | Exit mapping returns 0 for any syntactically valid ledger, even when counters indicate misses. | A–D: each negative control must exit nonzero as well as report its defect. | Yes, if selftest asserts nonzero exit for each negative arm; output-only assertions would miss it. Specify status assertions. |
| 10 | Exit mapping treats tool/input errors as TARGET_MET (or maps every nonzero internal command to success). | E: base revision with ledger absent must exit 1 and print `verdict=TARGET_MISSED ledger=absent`. | Only if selftest includes base-absent mode or equivalent; the selftest's exact arms are not in claims. Add explicit absent-ledger arm. |
| 11 | Selftest omits the empty-description arm, allowing descriptions made solely of whitespace (or empty after trimming). | C: blank/whitespace description must increment `empty_desc`. | **Live mutant:** claims require control (c) for the counter but do not guarantee checker selftest covers it. Add a hermetic blank/whitespace description arm and assert count + exit. |
| 12 | Selftest mutates the fixture tree in place and does not restore pristine bytes on failure, contaminating later arms or the caller's checkout. | All controls: run selftest twice / hash fixture before and after; results must be independent and bytes unchanged. | Not guaranteed by predicate or controls; hermeticity alone does not prove restoration. Add before/after hash and repeat-run control. |

## Freeze-time additions

At minimum, add explicit duplicate-row and whitespace-only-description selftest arms (mutants 8 and 11 are live against the stated controls). Also make the selftest contract assert exit status, not just printed counters, and verify fixture bytes remain unchanged after repeated execution. Controls (a)–(e) are runtime predicate kill controls; they do not by themselves establish selftest branch coverage.
