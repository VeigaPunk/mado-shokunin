# Ledger root cause — how `tools/mado-hostguard.py` and `tools/mado-keysym.py` fell out of the wave-seat tool ledger

Seat: `RevengerLedger` (round 51, w1). Lane: `/home/vgpnk/Projects/shokunin/mado-shokunin`.
Scope: reverse-engineer, from committed bytes only, why the only tool ledger in the lane missed two
tracked instruments, and derive the invariant a lane-level ledger must satisfy so the class cannot
recur. Nothing was run against the host; no compositor socket, no service, no lane file edited.

## Verdict

The ledger's **population enumeration was never the defect**. `check-ledger.py` derives the
instrument set from `git ls-tree` at a supplied revision (`:329`) and fails closed on a tool it
cannot account for (`:331-336`). What failed is the **revision the derivation was ever pointed
at**: the artifact is emitted at a pre-data commit, its only revision default is that same frozen
commit (`:673` → `:49`), it is generated from a hand-written literal row list that cannot absorb a
new tool (`:59-146`; generator row loop `:362`, `emit()` `:510-518`), and **no gate or seat in the lane runs it at a
scoring revision**. The instrument set is therefore complete for one commit and stale for every
commit after it — and three instances exist, each *exactly* complete at its own commit and wrong
the moment the round's own data commit landed. The two named tools are not a seat-knowledge
failure: the round-49 dispatch itself pinned the ledger's scoring revision to the round base, and
`mado-keysym.py` did not exist until 8 seconds after the ledger was committed.

That sentence is the whole root cause in the artifact's own words: **true of that revision**.

## 2. Population derivation, read from the bytes

Four separate mechanisms, only one of which is tree-derived:

1. **Enumeration (tree-derived, per `--rev`)** — `check-ledger.py:325` `entries = git.tree(rev)`;
   `:329` `tools = sorted(p for p, _ in entries if p.startswith("tools/"))`. `Git.tree` runs
   `ls-tree -r -z <rev>` (`:172-183`). Correct: the candidate population is the tree at whatever
   revision is asked for.
2. **Declaration (static literal)** — `declared = [r["tool"] for r in ROWS] + [e["tool"] for e in
   EXCLUDED]` (`:330`); `ROWS` is a 12-entry module literal (`:59-135`), `EXCLUDED` a 3-entry
   literal (`:137-146`). The declared set cannot grow from the tree.
3. **Detection (fail-closed, both directions)** — `:331-333` appends `"tool not covered: %s"` for a
   population member with no declaration; `:334-336` appends for a declaration that is not a tool
   at the revision. So the checker *can* report exactly the round-50 defect — if pointed at the
   right revision.
4. **Generation (cannot populate)** — the row loop is `for row in ROWS` (`:362`), and `emit()`
   (`:510-513`) writes only the derivations that loop produced, so the generator has no path from
   "a new tool exists" to "a row exists". Its own prose is a second static pin: `emit()` opens
   with the hardcoded string "Twelve instruments at the round-49 base" (`:518`, title at `:513`), so a re-emit at
   any other revision would print a false sentence unless a human edits the literal. At the round-51 base the generator refuses
   outright rather than emitting an incomplete ledger:
   `receipts/r49-emit-refusal-at-r51-base.txt` → `PROBLEM tool not covered: tools/mado-hostguard.py`,
   `PROBLEM tool not covered: tools/mado-keysym.py`, `LEDGER rows=12 excluded=3 problems=2`, exit 1.
5. **Revision default (the silent channel)** — `ap.add_argument("--rev", default=BASE)` (`:673`)
   with `BASE = "03e4ae76…"` (`:49`). `BASE` is used *only* as this default. A reader or gate that
   runs the checker without `--rev` gets a clean exit at a revision three rounds stale. Nothing in
   the lane ever passed a different `--rev` except the round-50 falsification seat.

Re-run at the round-51 base reproduces the defect on committed bytes
(`receipts/r49-checker-at-r51-base.txt`, exit 1):

```
PROBLEM tool not covered: tools/mado-hostguard.py
PROBLEM tool not covered: tools/mado-keysym.py
LEDGER rows=12 excluded=3 problems=2
```

as an uncovered tool by every later revision; `mado-hostguard.py` escaped the same way one round
later, into the same stale artifact.

## 4. The exact escape step

Named precisely, in the order the evidence supports:

**(a) Validity window — the artifact is scoped to a commit, the claim to a class.** The ledger
asserts a rule about "every blob under `tools/`" (a class, unbounded in time) and evidences it at
one commit (a point). The round's own data commit is *by construction* after the freeze commit, so
every instrument born in-round escapes the ledger that was supposed to cover it. That is an
ordering defect, and it is structural, not accidental: freeze-then-data is the lane's process.

**(b) Revision default — the stale window is the default.** `:673` makes `03e4ae76` what a caller
gets for free. The tool has no notion of "current tip"; it has a default, and the default is the
emit rev. Nothing in the lane overrode it.

**(c) No consumer — the ledger is a wave-seat deliverable, not a gate input.** At r50 tip, the only
tracked file outside `.ufo/` mentioning the ledger is a SCORECARD planning line
(`SCORECARD.md:2772`); `quality/`, the round-50 `registration.md`, the freeze, and every gate are
silent. Verified independently at r50 by `w2/RevLedgerR50` finding 2 ("no tracked lane-level
ledger/checker exists") and admitted first-party by the r49 seat itself: "The ledger is not wired
into `QUALITY.md`, `PROVINCE.md`, `README.md` or any gate" (`ScrToolLedger.md` §8). A checker that
nobody invokes detects nothing; the gap was found only when an adversarial seat chose to re-point
it (`RevLedgerR50`, `receipts/check-at-attack.txt`).

**(d) Scope predicate — `tools/` is not the instrument plane.** Independent of the two tools,
`:329` scopes the population to `tools/` only. At the round-51 base the C1 population is
`tools/*` + `quality/*.py` + `quality/counters/*.py` = **79** files; the r49 ledger names **15**,
and **0** of the 62 quality-plane instruments. Three of those — `quality/check-wave-done.py`,
`quality/check-state-cite.py`, `quality/check-deliverables.py` — were *also* born in the round-50
data commit `906178b6` and escaped by the same mechanism into a scope that could never have held
them. Even a perfectly refreshed `tools/`-only ledger would leave them uncovered. This is not a
growth problem either: at the ledger's *own* commit `dd2e827e` the predicate already excluded 15
`quality/*.py` and 42 `quality/counters/*.py` instruments, none named
(`receipts/population-counts.txt`). The scope was chosen wrong at birth and stayed wrong.

**Why this is not seat negligence or a seat-knowledge boundary.** The round-49 dispatch text pinned
the scoring revision into the seat's own instructions: "its last committed live-run receipt (path at
`03e4ae76aff7a4be59cb69970dd553baa319695a`, verified to exist with `git ls-tree`)" (`.ufo/waves/round-49/w1-spec.json`,
item `ScrToolLedger`). The seat did what it was told, at the revision it was given, and could not
have known about `mado-keysym.py`: that file did not exist at the time. Seat knowledge is the wrong
axis entirely — the defect is that correctness at a *given* revision was accepted as the deliverable.

## 5. The remedy that reproduced the mechanism

The round-50 falsification's own prescription was: "A retargeted checker must also move `BASE` off
`03e4ae76` (`check-ledger.py:49`) to the round-50 base and re-derive receipts there"
(`.ufo/waves/round-50/w2/RevLedgerR50.md`, "Deliverable" §). Re-pinning to the round-50 base would have been
§3's mechanism with a different number: the round-50 base `8ae47b95` predates the round-50 data
commit `906178b6`, which added `tools/mado-hostguard.py` and three `quality/*.py` instruments, so the
retargeted ledger would have been stale on landing. The persisting of a base constant is the defect; any fix that changes only *which*
constant is a rehearsal of it.

## 6. Invariant a lane-level ledger must satisfy

Stated so each part is falsifiable from committed bytes, and mapped to `PRED-C1-r51`
(`.ufo/waves/round-51/claims.md`) — an instrument plane that satisfies all six cannot reproduce
this class:

- **L1 — Population from the tree at scoring time.** The population is `git ls-tree` at the
  revision being scored, never a literal list, never a prior seat's knowledge, never a default.
  A hardcoded default revision is a defect even when the caller can override it.
  → claim: `--rev <rev>` is mandatory; `P` = files under `tools/`, `quality/*.py`,
  `quality/counters/*.py` at `<rev>`.
- **L2 — Fail-closed on both directions.** Every population member appears exactly once
  (`uncovered=0`); every ledger row names a population member (`dangling=0`). A row that names
  nothing is as fatal as a member with no row.
- **L3 — Scope is the instrument plane, not a directory.** The population predicate must cover
  every path class where a lane instrument can be born (`tools/`, `quality/*.py`,
  `quality/counters/*.py`), because instrument birth is not confined to `tools/`. §3(a)+(d): the
  ledger must be *complete over the class it claims*, not over one directory of it.
- **L4 — Invocation at the scoring revision, by a consumer.** The ledger is evidence only if a gate
  runs the checker at the same revision the round's verdict names, and the receipt is committed at
  that revision (this is round-50 routed defect D1 applied to the ledger). A ledger no consumer
  invokes cannot detect anything; the verdict must be produced, not inherit a stale default.
- **L5 — Growth is a landing obligation, not a seat's discretion.** Adding a file to the population
  without adding its row must break the gate at the very commit that adds it. Equivalently: the
  ledger's generation step must be re-run by whoever lands the instrument, and the gate is what
  forces it. The generator must be able to *populate* a declared tool (class, description,
  accountability pointer), so refusal-without-repair is visible rather than silent.
- **L6 — Non-vacuity.** The same command at the round base must MISS (`ledger=absent`). A predicate
  that cannot fail proves nothing; `PRED-C1-r51` carries this as `verdict=TARGET_MISSED` at
  `6ca8c559`.

Mapping to the frozen predicates: L1+L2 = the `population=<P> ledger_rows=<P> uncovered=0
dangling=0` terms; L3 = the choice of `tools/` ∪ `quality/*.py` ∪ `quality/counters/*.py` as `<P>`;
L4 = running `c1-r51-ledger.py --rev <rev>` and committing the receipt at that rev; L5 = the
`uncovered>0` and `dangling>0` kill controls, i.e. the gate fails at the commit that grows the
population without its row; L6 = the base clause (`verdict=TARGET_MISSED ledger=absent`, exit 1). The residual
weakness the freeze inherits — a caller passing a *stale but explicit* `--rev` still gets a clean
exit — is contained only by L4, i.e. by the gate's choice of revision, not by the counter.

## 7. Confidence and residual gaps

- **High** on the mechanism and chronology: every claim above is read from committed objects
  (`git ls-tree`/`log`/`show`) or from the artifact's own bytes with line anchors; the checker was
  re-executed read-only at `6ca8c559` and reproduced the two problems (`receipts/`).
- **High** that seat knowledge was not the cause: the r49 dispatch text pins the base
  (`w1-spec.json`), and `mado-keysym.py` postdates the ledger commit by 8 s.
- **Inference (marked)**: that the round-50 L1 did not run the checker at any revision. Direct
  evidence is the absence of a gate/receipt and the r49 seat's own §8 statement; the specific
  non-run of a command leaves no residue, so "nobody ran it" is supported by absence, not by a
  recorded failure. The round-50 spot-check's §6.5 routes the same class forward, consistent with
  this reading.
- **Not established**: whether a `quality/`-plane instrument was *deliberately* out of scope in
  round 49. The ledger's title and rule both say "`tools/`", so it was in scope by declaration and
  out of scope by predicate; intent is not recoverable from the bytes and does not change L3.
- Out of scope per seat bounds: whether the L1 adopts this invariant, and the content of the actual
  round-51 ledger/checker — those are `w1` build seats and the L1 freeze.
