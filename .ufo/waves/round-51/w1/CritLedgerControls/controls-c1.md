## Cheapest do-nothing control that would pass

None under the frozen predicate. With a clean ledger, every member of the population must have exactly one row, so the population-to-ledger path multiset must be equal; no path can be omitted, duplicated, or replaced by a non-population path. Every row also independently requires a non-empty description and a basename-containing pointer. Thus there is no shorter population-vs-ledger diff that passes by omission or padding. A mechanically cheap pass can be generated by copying the complete population paths and reusing one non-empty description and a pointer file that contains each basename—but that is still complete row-by-row coverage and valid accountability, not a do-nothing bypass; description usefulness is not part of the frozen predicate.

## Precision caveat for L1 freeze

The task's requested `(a)`–`(e)` output strings are literal only after P, C, the five newest basenames, and the absent-ledger reporting form are fixed by the checker implementation. Do not guess numbers or let a mutant mutate the revision; emit exact decimal values and the actual revision hash when materializing receipts. In particular, claims.md explicitly freezes base output as `verdict=TARGET_MISSED ledger=absent` (exit 1), whereas the sibling design prompt proposes a common counter line; the frozen claim wins, so control (e) should use the exact `ledger=absent` form unless the counter's prescribed final-line schema resolves this in a way consistent with that sentence.
