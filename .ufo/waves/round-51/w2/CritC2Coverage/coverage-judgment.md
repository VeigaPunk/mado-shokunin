## Important omissions / unsupported claims
1. **No behavioral closure:** no dispatch or resulting UI/action effect is measured. Do not read “dispatcher execution surface” as proof that a user action succeeds on this host. This omission is explicitly bounded, not a predicate failure.
2. **Incomplete dispatcher semantics:** only five implementations' argument readers are inspected; the remaining 66 are counted, not traced (entry `Limits` lines 291–293). Therefore “each dispatcher reads its own way” is demonstrated by examples, not universally established.
3. **Host branch provenance is thinner:** the entry says the manager-selection implementation pin (`Hyprland-ConfigManager.cpp`) was rejected as a registry row and step 9 relies on held config-era knowledge plus a host file listing (lines 234–243, 298–300). This supports a host-specific inference, not a sourced claim that every 0.56.2 host takes that branch.
4. **Some deductions are explicitly `[INF]`:** repeat/long-press `pass` consequences depend on flags being combinable (lines 131–135, 288–290); the entry itself does not establish that configuration is accepted.
5. **Not all pin-manifest files are admitted sources:** four pins have no registry row and are cited only in Limits (lines 50–53); they cannot support an expanded mechanism claim. Existing wiki documentation describes a different Lua branch (lines 240–243), so it must not be generalized as the host's executed grammar.
