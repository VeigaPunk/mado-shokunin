**Impacted axes:** C1 coverage attribution; operability/safety is a plausible alternate characterization, not a second independently earned axis.

**Smallest safe correction / recommendation:** retain the existing narrow wording: three new classes of setup refusal under a deliberately narrower input grammar. Do not advertise three newly modelled desktop configurations, protocol-mandated uniqueness, or domain mastery. Whether refusal-class coverage qualifies for the assigned coverage axis is a canonical-judge classification question; relabeling it after measurement would not establish the frozen claim.

The three new controls require rc2 and the setup-stage marker. `c1-r84-namespaces.py:278-283` does not require a namespace-specific explanation: an unrelated setup refusal with the same stage/rc would satisfy an individual new case. This is a finite-oracle specificity limitation, not evidence the inspected implementation takes that shortcut.
