### VCS: no commit or ref update is not a no-write guarantee

The earlier table mixes several effect boundaries. Preserve the pinned Git/jj facts, but do not interpret a “no” cell as authorization under a strict no-VCS/index/repository-write assignment:

- S099 establishes that `git commit --dry-run` creates no commit; `--short`, `--porcelain` and `--long` imply dry-run and `-z` implies porcelain when no format is supplied. `git commit -n` remains `--no-verify`, not dry-run. None of these facts establishes absence of object-database or index-cache writes. The original tree/index-cache qualification remains valid. The independent review records `git commit -zn` changing the index and creating an unreferenced tree while HEAD stays unchanged.
- S100's documented add dry-run behavior and the measured unchanged-index `git add -n`, `-nv` and `-An` examples remain historical facts for those forms and conditions. They do not compose into an all-options no-write guarantee: the review records `git add -Nn new.txt` creating an unreferenced empty-blob object without adding an index entry. Do not generalize that exception into a claim that every bare `-n` writes.
- S101's `git push -n`/`--dry-run` sends no ref update, but contacts the remote and runs the pre-push hook. No ref update is not a guarantee of no hook side effects.
- Preserve S102's actual help parsing and option-value distinction: a help-looking token consumed as a message is data, not a help exemption. Preserve the existing distinction between jj clap help and `jj help` dispatch without workspace loading, and the user-alias caveat; do not infer a universal safe-help rule for unknown aliases.
- Preserve S104's early return before pushing: ordinary `jj git push --dry-run` can still snapshot the working copy. The historical `--ignore-working-copy` push dry-run no-change measurement is scoped to its tested up-to-date case, not every jj command.
- `--ignore-working-copy` suppresses a snapshot, not all repository mutation. The independent review records remote-configuration changes from `jj git remote add`, bookmark removal from `jj bookmark forget`, and workspace creation/registration from `jj workspace add` despite exit 1, all with that flag. Both compared tools returned clean for these three cases. Failure status does not prove rollback or no write.

Under a strict no-write contract, count changes to repository objects, index/cache, operation/bookmark/workspace/remote configuration, working copy and remote refs as relevant effects; hook effects require separate consideration. A dry-run/help label or a clean transcript scan cannot grant permission. This distinction preserves true command semantics without silently narrowing the assignment's safety boundary to commit/ref updates.
