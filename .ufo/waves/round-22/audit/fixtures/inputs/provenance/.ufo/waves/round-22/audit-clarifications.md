# C2 pre-implementation contract clarifications

Written after independent schema review and before any candidate implementation/measurement. These clarify validation/evaluation order, not a selected green target.

- BUNDLE is a JSON object. Its snapshot path resolves relative to explicit ROOT, never bundle parent. Reject absolute, empty, dot/dotdot, backslash paths and every symlink component. Inputs are bounded to2MiB. Snapshot SHA is exactly64 lowercase hex characters; uppercase is invalid input2.
- Read bounded snapshot bytes and verify digest before JSON decoding/shape/verdict comparison. Digest mismatch gives code2, finding_id snapshot_tampered; do not compare malformed bytes as semantic results.
- Missing files/findings keys are invalid2, never defaulted empty. files must be nonempty. Finding evidence must be explicit observed|lead; absence or another marker is invalid uncertainty2, not an inferred observed row. The audit cannot restore missing evidence labels from the r19 markerless output.
- All counters must have exact int type (bool invalid), be nonnegative, and JSON numbers must be finite. Require nonempty strings after strip for finding class/command. Duplicate keys anywhere, malformed JSON and invalid shapes give2 evidence_audit_input_invalid. Extra metadata keys are permitted and ignored; they never override normative fields.
- Evaluate every count/clean assertion against ACTUAL validated row/error counts, not claimed counts. Each per-file counter is separately summed; no deduplication is implied. clean:false is a conservative non-clearance assertion and can accompany zero findings/errors; clean:true requires both actual findings and errors zero.
- Collect all applicable contradiction IDs as a sorted unique list; consistent assertions return0 with exactly evidence_audit_clean. Fixture expected.code is normalized from exact JSON int0/1/2 or string0/1/2 at assembly, with the original retained and normalization recorded; arbitrary strings/types refused. This representation normalization does not change semantic verdicts.
- The r19 six-row example can be used ONLY with explicit derivation provenance: preserve original markerless receipt unchanged, retain later authoritative5-observed/1-lead interpretation separately, and call the markerful snapshot a derived audit input. It is not the original r19 output, not a new detector run, and not semantic precision evidence or retroactive C3 admission.
