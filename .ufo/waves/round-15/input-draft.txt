# Input layers are documented interfaces, not delivered application input

This entry adds U6's **documented input-debugging layer route**, not raw capture,
injection, kernel diagnosis or successful delivery to an application.
`[INF-docs]` marks upstream documented or XML-declared semantics;
`[OBS-static]` marks package and installed-byte observations made without
execution; `[UNK]` marks behavior not exercised.

## Layer ladder

| Layer | Opened anchor | What the layer can establish | What it cannot establish |
|---|---|---|---|
| Kernel event node | `[INF-docs]` S051 §Helper tools :31-32 | Input tooling reaches the kernel's `/dev/input/event*` nodes and most of it requires root. | `[UNK]` Which nodes exist here, whether any is accessible, or whether libinput recognized one. |
| libinput device context | `[INF-docs]` S051 §libinput list-devices :34-79, §libinput list-kernel-devices :81-128 | `list-devices` reports devices libinput recognizes plus its built-in defaults; `list-kernel-devices` separates kernel-known devices from libinput-recognized ones. | Desktop/compositor configuration, compositor policy, or any event delivered to a client. |
| Event observation class | `[INF-docs]` S051 §libinput debug-events :130-201, §libinput record and libinput replay :204-388 | A recording is a kernel-event sequence independent of the libinput context; record obscures key codes by default; replay builds a virtual device from the log. | That an observed kernel event was routed, filtered or accepted by the compositor or an app. Replay is injection-class, not observation. |
| Compositor policy and focus | `[INF-docs]` S052 wl_keyboard.enter :2614, wl_keyboard.leave :2635, wl_pointer.enter :2197, wl_pointer.leave :2212 | Focus is a compositor decision scoped to a `wl_surface`; enter/leave order and the one-active-surface rule are protocol obligations. | `[UNK]` Which policy rule or device binding this compositor applied, or which surface it focused. |
| Wayland client delivery | `[INF-docs]` S052 wl_seat.capabilities :2030, wl_seat.get_keyboard :2075, wl_keyboard.keymap :2600, wl_keyboard.key :2669, wl_pointer.motion :2224, wl_pointer.button :2244, wl_pointer.frame :2313 | Capability events gate object creation; key codes require a keymap; pointer coordinates are surface-local and grouped by `frame`; button codes come from the Linux input header. | `[UNK]` That this compositor created a keyboard/pointer object for any client of this session, or sent it enter, key, button or motion events. |
| Toolkit and application | No opened source in this entry | Keymap interpretation, shortcut matching, text input, IME composition and app response are client-side concerns beyond these interfaces. | `[UNK]` Any delivered keystroke, composed text or application outcome. |

The ladder is deliberately top-down: a fact at one layer never substitutes
for the layer below it. A device recognized by libinput, an event type
declared in the XML, and an advertised seat capability are three different
observations, none of which is delivery.

`[INF-docs]` S052 wl_seat.capabilities :2045-2056 adds a flap rule: a
`wl_pointer` object of version 5 or later created before the most recent
added-capability event must not send events; the same applies to
`wl_keyboard`. A capability flap therefore leaves stale objects inert and
requires a fresh `get_pointer`/`get_keyboard`; asking for an object on a
seat that never had the capability is a protocol violation (:2068-2084).

Between libinput and the client sits compositor policy. The XML quotes
below establish only that focus is compositor-decided and surface-scoped.
The current Hyprland wiki documents read-only info commands (`hyprctl
devices`, `hyprctl getoption`, page anchor `#info`) that would address the
device list and input option values. That route is named, not executed,
contributes no value here, and is outside this entry's two-source join.

## Safe boundary

- Read-only inputs only: the two immutable tag URLs and static package
  queries. The installed XML was hashed, never parsed as live protocol.
- `[INF-docs]` never becomes a host fact by citation. Only package
  presence, byte counts and hashes are `[OBS-static]`.
- Package drift was observed, not caused here: `libinput` read 1.31.3-1
  earlier in this wave and 1.32.0-1 at recheck. This seat installed or
  upgraded nothing. Whether the running compositor started against, links,
  or now uses 1.32.0 is `[UNK]`; a matching package version is not
  running-compositor equivalence.
- Documentation and package now share the 1.32.0 number, but that is a
  version label, not evidence about this compositor's input behaviour.
- Prohibited and not performed here: every `libinput` subcommand
  (`list-devices`, `list-kernel-devices`, `debug-events`, `debug-gui`,
  `record`, `replay`, `measure`, `analyze`, `quirks`), sudo, opening
  `/dev/input/event*`, event observation, recording, replay, injection,
  raw device reads, kernel/DRM diagnosis, any `hyprctl` call, compositor
  reload or configuration write, and any text-input/IME client.
- `libinput record` and `libinput replay` are not neutral observers:
  record is a capture-class privacy surface and replay creates a virtual
  device. Neither is a permitted checking step, and neither was run.
- No device name, node path, seat name, keycode or raw event is retained
  by this entry.
