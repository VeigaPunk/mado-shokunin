**Round-55 refinement (append-only; one read-only tool, four record instruments, one knowledge entry and one errata correction; no new write surface):** `tools/mado-kbdopts.py` is a read-only join. It reads only the files its caller names: each `--config` path (Hyprland config text, regular files, 1 MiB cap) and at most one `--getoption` path (a captured `hyprctl getoption -j` reply). From these it computes the effective per-keyboard `input:repeat_rate`, `input:repeat_delay` and `input:numlock_by_default` values under the hyprlang 0.6.8 subset it models, and compares the global values with the live reply. Anything outside that subset is reported `unsupported`, never guessed. It starts no process, opens no socket and writes nothing; the operator captures the `getoption` reply with the read verb and applies no change. The round's record instruments are `quality/counters/c1-r55-kbd-entry.py` (PRED-C1-r55, the entry's counter), `quality/counters/c3-r55-p19.py` (PRED-C3-r55, the errata correction counter), `quality/check-r55-controls.py` (the independent harness that builds the frozen negative controls in scratch git repositories and runs the counters and the C2 fixtures as child processes under its `--work` directory) and `quality/check-freeze-order.py` (the freeze-order gate delivered as the M54-2/M54-4 mistake fix; its input contract is not stated in the frozen registration and is unverified until it lands). The counters and harness write only under `--work`; none touches a config plane, the compositor, a socket or a host service. Keypress delivery, client-side repeat and the seat's numlock state are outside every instrument.
