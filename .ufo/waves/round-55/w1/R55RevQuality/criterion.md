# Draft criterion 106 (text only; not registered in corpus/QUALITY.md by this seat)

106. **A frozen contract is committed strictly before the launch record that binds it, and the launch record names the freeze** — For each wave of a round that registers a frozen contract, let F be the first commit that adds the round's `claims-frozen.md` (or `registration.md`), and L the first commit that adds the wave's `<wave>-dispatch.json`. The round passes only when every leg holds: (a) F is an ancestor of L and F ≠ L (`git merge-base --is-ancestor F L`, then `F != L`), so the contract and the launch payload were not committed in one step; (b) the earliest launch instant read from a committed record (the dispatch registry `createdAt`, the `<wave>.ready.dispatched` line, or a launch time quoted in `<wave>-results.json`) is later than F's committer instant (`git show -s --format=%cI F`); (c) the committed launch record contains F's full sha, or the sha256 of the frozen file bytes; and (d) no frozen path differs between F and the scored revision REV (`git diff --quiet F REV -- <frozen paths>`). A wave whose launch record is untracked, carries no instant, or names no freeze reads `UNPROVEN`, never `OK`. Each instant is printed with the field it came from; the checker reads the earliest instant it finds, so a second committed instant that is earlier cannot be hidden by a later one. Check: `python3 -I quality/check-freeze-order.py --repo . --rev REV --round N` prints one `FREEZE_ORDER: round=N wave=<w> freeze=<F-sha> freeze_at=<iso> launch_at=<iso|none> src=<field> same_commit=<y|n> bound=<y|n> frozen_diff=<k> order=<OK|LATE|UNPROVEN>` line per wave whose dispatch file is committed, then `CHECK106: waves=<a> ok=<b> late=<c> unproven=<d> verdict=<OK|FAIL>`; exit 0 only on `verdict=OK`, 1 otherwise, 2 on setup error. Shown able to fail, on round-54 committed objects: `git log --diff-filter=A --format=%H -- .ufo/waves/round-54/w1-dispatch.json` → `350d30e4ec5531f65ce99a57efeb8216f38e678a`, the same commit that `git show -s --format=%cI 350d30e4ec5531f65ce99a57efeb8216f38e678a` dates `2026-10-27T14:11:10-03:00`, so `same_commit=y`; `git show a67195cca6e332471c4bb0aaf8083498286f988f:.ufo/waves/round-54/w1.ready.dispatched` first line `2026-10-27T14:06:21`, and `git show 9ea87392857d26ae023512979ea1bea8b66bbb61:.ufo/waves/round-54/w1-results.json` line 52 prose "after w1 dispatch (14:05:25) and ready (14:05:28)", so the earliest instant precedes F; the dispatch file at `350d30e4` contains no freeze sha, so `bound=n`; `git cat-file -e e25149fe:.ufo/waves/round-54/registration.md` exits 128 at base. Lesson grounding: lessons/round-54.md#mistakes M54-2 and M54-4 (with round-53 M53-4).

Declared limit: committer instants and the dispatcher's `createdAt` are writer-settable, so legs (b) are as honest as the dispatcher. Legs (a), (c) and (d) are the stronger evidence: a launch record cannot contain F's sha before F exists, and ancestry plus the unchanged frozen bytes do not depend on any clock. The check proves that the committed record post-dates the freeze object at REV; it does not prove when a seat first read the wave, and it counts only waves whose dispatch file is committed. An untracked `.ready` marker is invisible to it by design, which is why the verdict is `UNPROVEN` rather than `OK` when no committed record carries an instant.
