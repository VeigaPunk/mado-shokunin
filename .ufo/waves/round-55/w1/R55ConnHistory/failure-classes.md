## 4. Defects found in the frozen contract (reported, not edited)

- **D1 — QUALITY 64 fails at freeze.** The registration and the claims name `quality/check-freeze-order.py`, `quality/check-r55-controls.py`, `quality/counters/c1-r55-kbd-entry.py` and `quality/counters/c3-r55-p19.py`. Running the QUALITY 64 command (`git show <freeze>:<registration>` grep, then `cat-file -e`) at `54dacbd` prints four `MISSING` lines. Under QUALITY 61 the registration's own commands also cannot run verbatim at freeze (`receipts/criterion64-freeze.txt`). Consequence: the predicates are the counters a seat writes after dispatch, which QUALITY 64 says are data, not predicates.
- **D2 — the C1 K17 row cannot pass `source_cell` as written.** R l.29 (`source_cell`) requires the registry URL to "end with the pin's `source_suffix` and contain the frozen commit". K17's pin is `wayland-1.26.0-wayland.xml`; its `source_suffix` is `1.26.0/protocol/wayland.xml`; the only registry row with that suffix is `S052` (`https://gitlab.freedesktop.org/wayland/wayland/-/raw/1.26.0/protocol/wayland.xml`). That URL has no `efb50993` (grep count 0), and no new row (S378–S380) covers it. Reconstruction: `K17_row_legs_with_S052: FAIL source_cell:K17` (`receipts/leg-reconstruction-forged-row.txt`, `receipts/sources-k17-wayland.txt`). Under the frozen text C1 cannot reach `rows=18/18`, so the kill rule fires by construction. This is a contract defect, not a seat failure; it needs an L1 ruling before any seat is scored against C1.
- **D3 — C1-CTL-7 cannot produce its named leg.** R l.47 mutates `frozen-tables.json` in the scratch tree and requires `missed` to name `pin_hash`. The same mutation changes the file the counter checks with `tables_sha` (R l.33: "frozen-tables.json differs from the embedded constant"). R l.7–8 says counters "refuse a tree whose frozen-tables.json differs", which is a setup refusal (exit 2), not a `missed=` line. The control either trips `tables_sha` (not `pin_hash`) or never reaches the counter's leg logic. The frozen text does not say whether the required leg must be exclusive.
- **D4 — "no normalization" vs the C3 strip.** C l.8–9 says no normalization. R l.120–121 requires "exactly the stripped pin line", and `freeze-verify.py` uses `.strip()`. The strip set is not defined in the contract.
- **D5 — shared registry as claim evidence.** R l.52–53 says the L1 writes S378–S380 at integration, and R §C1 `source_cell`/`new_rows` read those rows. C l.72–76 ("Causal separability") says shared record files are "integration surfaces, not claim evidence". The frozen tables do not freeze the S-id per K row (the seat picks it), so the K→S binding is seat-chosen and checked only against a row the L1 may also write.
- **D6 — receipt list mismatch (minor).** C l.4 lists `receipts/{before,census-before}.txt` as committed; `receipts/freeze-verify.txt` is also committed and R l.7–8 cites it. The two lists disagree.
- **D7 — marker not committed (minor, QUALITY 70).** `.ufo/waves/round-55/w1.ready` is on disk (dispatch marker `w1.ready.dispatched` present at 19:52) and absent from `HEAD`'s tree. The contract is silent; QUALITY 70 would read it as `UNTRACKED` at closure.
- **D8 — the freeze verifier reads the working tree.** `freeze-verify.py` uses `open()`, not `git show`. The rule at R l.11–13 is stated for counters and harnesses, not for this tool, so it is allowed. The freeze receipt attests the worktree at freeze time (QUALITY 63). I reran it on a `git archive` export of the commit, and it matches.
