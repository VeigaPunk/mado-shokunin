## 4. Defects and ambiguities (for the L1; the seat did not reinterpret the contract)

**D1 — K17 source leg is unsatisfiable as the registration words it (contract).** `registration.md` §C1 `source_cell` requires the registry URL to "end with the pin's `source_suffix` and contain the frozen commit". S052's URL in `corpus/SOURCES.md` (at the freeze commit) is `https://gitlab.freedesktop.org/wayland/wayland/-/raw/1.26.0/protocol/wayland.xml`: it ends with the suffix `1.26.0/protocol/wayland.xml` but contains no `efb50993…`. Literal reading → `source_cell:K17` missed in every case. Evidence: `verify.txt` `ROW K17 … url_has_freeze_commit=False`. Decision needed: a tag-pinned rule for wayland (URL contains the tag `1.26.0`, plus the pin sha256) — which is a change to the counter, not to this draft.

**D2 — K16 quote contains `|` (frozen grammar conflict).** `frozen-tables.json` `c1.k` K16 quote is `if ((!VAL || !VAL->m_bSetByUser) && !fallback.empty())` (pin `Hyprland-legacy-ConfigManager.cpp:1119`, quote verified on that line). The registration grammar says "no `|` inside a cell". The row cannot be both byte-equal to the frozen quote and free of `|`; in a markdown table the `||` splits the row. I emitted the quote byte-equal (`gen_entry.py` `row()` has the explicit exception for `||`, commented), so a `|`-splitting counter will read K16 as malformed (`row:K16`/`quote:K16`). Decision needed: an escape rule in the grammar (which breaks byte-equality) or a quote-row exception. The verifier flags it as `GRAMMAR K16` under SEAT.

**D3 — S378–S380 absent at the freeze commit (dependency, not a defect).** `corpus/SOURCES.md` at `54dacbd` has no S378/S379/S380. The draft cites them (K10→S378, K11/K12→S379, K18→S380; E-rows too). Verified only with synthetic rows built from the registration text (`SYNTHETIC … round 55 seat check`, scratch only, not written anywhere): `NEW_ROWS 3/3`, K10/K11/K12/K18 `source ok`. The L1 must write the rows with the exact URLs and `used-by` = `corpus/knowledge/hyprland-keyboard-repeat-numlock-r55.md`.

**D4 — trio and index.** The `source:` trio lines name S378–S380 that do not yet exist (same dependency as D3). The `corpus/README.md` index row is the L1's; not written.

**Ambiguity A1 — the source-level first send at bind.** `repeatInfo` (Seat.cpp:442–445) compares against `m_lastRate`/`m_lastDelayMs`, and nothing in the pins initialises them. Whether the first `repeat_info` after `wl_keyboard` creation (Seat.cpp:350) is dropped when the stored pair equals the uninitialised/initial values is **UNKNOWN**. Needed pin: `src/protocols/core/Seat.hpp` at efb50993 (not in `fetch/`). Stated in the entry as UNKNOWN; not promoted.

**Ambiguity A2 — `getDeviceInt` body is not pinned.** The device-before-global rule is held only for `getConfigValueSafeDevice` (K16). The link is marked INFERENCE. Needed pin: the `getDeviceInt` definition (legacy `ConfigManager` header/source around the device helpers).

**Ambiguity A3 — negative or out-of-range repeat values.** Whether hyprlang rejects, clamps or passes a negative `input:repeat_rate` before `applyConfigToKeyboard` is not in the pins. If a negative value reached the clamp (`std::max(0, …)`, K04/K05) it would be stored as 0, which the protocol reads as "disable repeating" (K17). Recorded as a chain consequence, UNKNOWN as a host fact. I did not check the round-46 `hyprlang-config.cpp` pin for range handling this seat; not checked.

**Ambiguity A4 — `m_keymapOverridden` writers.** Only the default (IKeyboard.hpp:94) and the check (IKeyboard.cpp:61) are in the ten pins. The header comment (IKeyboard.hpp:91–93) names virtual keyboards with custom maps as the case. Any writer outside the pins would make the early return at IKeyboard.cpp:61–63 reachable, and then the push at IKeyboard.cpp:147 would be skipped on that path. Reach UNKNOWN (E22, E25 say so).

**Ambiguity A5 — non-minor source observation (for the reviewer).** InputManager.cpp:1271 compares the raw `REPEATRATE`/`REPEATDELAY` with the stored clamped values; for a negative raw value the early-return test is never true, so it re-applies every time. Harmless (the store clamps again), noted only.

**Ambiguity A6 — host scope.** `host-input.conf` is `input.conf` only. `hyprland.conf` and any file it sources are not pinned, so a `device { … }` block elsewhere is not excluded. `hyprctl devices -j` was not read, so the host's effective per-keyboard value is not established here (C2's tool is the join).
