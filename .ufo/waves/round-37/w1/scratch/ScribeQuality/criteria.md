62. A zero count is evidence of absence only when the same channel, in the same round, is shown to carry the class being counted: a positive probe — at least one line from the same logger at the same level, inside the same window as the count — is counted beside the zero and committed in the same receipt. Without that probe the reading is refused, not read as a negative; a channel that carries other loggers, other levels, or the same logger only before a gate closed proves nothing about the markers. Round-37 application: Hyprland v0.56.2 writes both event-socket markers as core-logger `ERR` lines (`.ufo/waves/round-37/fetch/S189.bin` EventManager.cpp:155 `failed writing event`, :175 `overflowed event queue, removing`), and the core logger returns before writing whenever `debug:disable_logs` is set (`.ufo/waves/round-37/fetch/S214.bin` Logger.cpp:15-16, :48); `hyprctl getoption debug:disable_logs` reads `"int":1` on this host (`.ufo/waves/round-37/fetch/S213.receipt.txt`). The session log's 27,331 lines hold 21 core-logger lines, all `DEBUG`, the last at line 21, three lines after the second config load at line 18, and no core `ERR` line. The unit journal holds 42 core `DEBUG` lines — two starts' stdout mirror, written before the loaded config turns stdout off (Logger.cpp:32, :47) — and no core `ERR` line. Both marker zeros are therefore refused (`S242`, refused at `.ufo/waves/round-37/assimilation/renumber-map.md:22`). A probe from a different logger does not qualify: the receipt's `drm: getCurrentCRTC` probe (`in_log=7`) and the log's 31 `ERR from aquamarine` lines show that the log carries aquamarine, not that it carries the core logger. Check: count same-logger, same-level lines in the channel after the window opens — `awk -v p=<last config-load line> 'NR>p && /^ERR \]/' <log> | wc -l` (here `p=18`, output `0`); a record that reads a zero as absence while that probe prints `0`, or whose receipt carries no probe count, violates this criterion. Extends criterion 43; a null channel is an unknown, not an observation. Limit: a positive probe shows the channel carried the class somewhere in the window, not at the instant of the event; the probe and the count must cover the same window, or the window is narrowed to where both are measured. 63. A receipt observable read from the working tree rather than from a revision — `git status`, `git diff` without a revision, a file's presence, size or mtime on disk — commits its raw witness beside the receipt in the same commit, and the receipt names the witness path and the command that produced it, so the observable is re-derived from the witness's committed bytes by one stated rule after that worktree is gone. A receipt header that discloses a reading as non-reproducible is a disclosure, not a witness. The witness is taken without writing the index: `GIT_OPTIONAL_LOCKS=0 git status --porcelain -- <paths>`, because plain `git status` may refresh the index stat cache, the hazard `tools/mado-verify.sh:3668` already guards against. Round-36 application: `quality/check-evidence-pointers.py:171-180` measures `inherited_dirty` with `git status --porcelain`; `.ufo/waves/round-36/receipts/before-pointers.txt:4` records `inherited_dirty=10` from the live tree, while its own re-run (line 12) reads `inherited_dirty=0`, and `.ufo/waves/round-36/receipts/` holds no porcelain witness, so the 10 re-derives from no committed bytes. Check: list the worktree reads with `git grep -nE '"(status|diff)", *"--|git (status|diff) --' <rev> -- quality/ tools/`; for each observable they feed, `git ls-tree --name-only <rev> -- <witness>` must list the witness, and `git show <rev>:<witness> | grep -c .` must equal the receipt's value. An empty `ls-tree` or an unequal count is a violation. Extends criterion 50; 50 commits ephemeral bytes a claim leg depends on, this commits the working tree's own reading. Limit: a witness shows what the tree read when it was taken, not that the tree held still until the receipt was written; a witness and a receipt produced by separate commands carry that TOCTOU gap and say so. (lesson: lessons/round-36-verifier-spotcheck.md R5)
