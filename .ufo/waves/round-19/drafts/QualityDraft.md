## Round 19 — durable anchors, supersession sweep, self-application (outside R18-V1/V2/V3/V4)

Criteria 27–29 are not restatements of 7, 9, 13, 23 or 24. Criteria 7 and 13 bind a hash to committed bytes and require a committed path for evidence that outlives a round; a committed digest of a rotating GitHub tree page satisfies both and still fails 27, which asks whether the upstream an anchor names can be re-obtained to the same bytes. Criterion 9 binds an audit verdict to a commit; 28 concerns a superseded present-tense value still stated in owned files, which is a property of the file set and passes 9 untouched. Criterion 23 binds a verdict token to the receipt that carries it; 29 says when a criterion's own red and green evidence is credited at all, a counting rule that 23 does not state. Criterion 24 requires a sentence relying on a receipt to name its producer; 29 reuses that requirement on the criterion-level evidence, so its receipt sub-clause overlaps 24 by design, and its distinct content is the rule that a criterion without self-satisfying red and green receipts is not counted as shown able to fail.

27. A credited source row's anchor is reproducible: tag- or commit-pinned bytes with their sha256, a content-addressed object id, or a registry checksum. A sha256 of a per-fetch body (HTML page, API listing, docs site whose bytes vary per fetch) never anchors a row, and an unversioned alias (`latest`, `main`, `master`, `HEAD`) never serves as version-specific support; the superseding row names the replaced id.
