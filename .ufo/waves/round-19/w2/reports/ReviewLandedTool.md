### Findings, by severity

1. **[MEDIUM] Ambiguous abbreviations are falsely reported as absent.** The script accepts 4–64 hex characters (`/home/vgpnk/Projects/shokunin/mado-shokunin/.ufo/waves/round-19/landed-check.sh:57-63`). When commit peeling fails, it treats *any* failed `git cat-file -e` as absence and prints `MISSING` (`:129-137`), although the public contract defines `MISSING` as “object absent locally” (`:25`). On the live lane, `git cat-file --batch-all-objects --batch-check='%(objectname)'` found 3,152 objects, including 87 ambiguous four-hex prefixes. For prefix `02ab`, `git rev-parse --verify --quiet '02ab^{commit}'` failed with “short object ID 02ab is ambiguous”; `git cat-file -e 02ab` returned 128 and listed two existing blobs (`02ab05a39f043868fc5ff35986c7f7e38d1d3eef` and `02ab27b6e16df6cb7fb4f8afee1a116de19dc7dc`); the tool nevertheless printed `MISSING 02ab` (exit 1). A `/tmp` fixture also produced two commit candidates for prefix `01c6`; the tool printed `MISSING 01c6` for that ambiguous commit prefix. Thus the accepted abbreviated-hash contract does not distinguish ambiguity from absence. The live lane had no four-hex prefix shared by two commits, but it did have the ambiguous blob prefixes above; the fabricated commit-pair fixture confirms the same code path for commit ambiguity.

2. **[MEDIUM] Ambient Git variables can silently change which repository and objects are classified.** The script sets prompt/lazy-fetch/optional-lock variables but does not clear caller `GIT_DIR` or `GIT_OBJECT_DIRECTORY` before its `git -C "$LANE"` calls (`/home/vgpnk/Projects/shokunin/mado-shokunin/.ufo/waves/round-19/landed-check.sh:71-88, 104-110, 127-142`). In a `/tmp` fixture, `GIT_DIR=/tmp/atk-landed/hijack2/.git` made a call for commit `3d94950ba31e510f28b7991450f99f7562b59ebf` print `MISSING`, despite that commit being the lane2 checkout’s local `HEAD` (and hence a local-only commit); the hijack repository lacked it. Conversely, `GIT_OBJECT_DIRECTORY=/tmp/atk-landed/hijack2/.git/objects` made the tool print `LOCAL_ONLY dc65b98c50d42fe0277819c489e30d56635de053` even though `git -C /tmp/atk-landed/lane2 cat-file -e dc65b98c50d42fe0277819c489e30d56635de053` failed: that object existed only in the injected object directory. The resulting reason also said `refs/heads/master absent locally`, although lane2 has that ref under its normal environment. This is a classification-integrity issue, not an observed write: the Git commands remained read-only. The fleet’s `/home/vgpnk/Projects/shokunin/mado-shokunin/.ufo/waves/round-19/w1/reports/ConnSiblingTripwire.md:34` records the related GIT_DIR fixture hazard.

3. **[LOW] Failure diagnostics from `ls-remote` are discarded.** The command redirects `ls-remote` stderr to `/dev/null` and emits only a generic failure (`/home/vgpnk/Projects/shokunin/mado-shokunin/.ufo/waves/round-19/landed-check.sh:87-88`). With an origin set to `https://127.0.0.1:1/nope.git`, the tool returned exit 2, zero stdout lines, and only `landed-check.sh: git ls-remote origin refs/heads/master failed in lane5`; the underlying connection error is not observable. Failure is safely non-LANDED and the exit map identifies exit 2 as unevaluable (`:32-34`), but an operator cannot distinguish auth, DNS, connection, or timeout failure from the tool’s message.
