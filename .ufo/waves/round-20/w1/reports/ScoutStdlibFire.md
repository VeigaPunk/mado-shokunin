## Observed shape facts a repair must respect

1. **Bare import is the harm shape.** A single cell `from shutil import which\nwhich(['sudo','pacman','-S','foo'])` at
   e629f73 emits 2 rows, no evidence key, exit 1; the same two cells split across two
   messages (import in cell 1, call in cell 2) also fires, exit 1; both are clean at
   9c54c56 (`/tmp/mado-r20-ScoutStdlibFire/probes3/multicell_import_then_call.jsonl`,
   sha256 `fcc19de43fec9c3836ff2e3d6fdbf65da6421c84dd150a51661de3746d664fc2`).
2. **The attribute form never fires at either revision.** `import shlex; shlex.join([...])`,
   `import shutil; shutil.which([...])`, `import os.path; os.path.join([...])`, and the six
   other attribute probes are all clean (`probes/attr__*.jsonl`). The lead branch requires
   an `ast.Name` callee (`tools/mado-tripwire.py:1431`), so `M.N` is never classified.
3. **The alias form fires too.** `from shutil import which as op; op([...])` is exit 1 at
   e629f73 and clean at 9c54c56; `from os import system as op; op([...])` fires at both
   revisions (correctly — `os.system` spawns), showing why alias canonicalization exists.
4. **The trigger is a literal argv list**, not a literal string: `from shutil import which; which('sudo')`
   is exit 0 at both revisions (no list argument, `helper_argv_leads` at
   `tools/mado-tripwire.py:1379-1390` only reads list/tuple shapes). All P-family cases
   must use a list.
5. **The class is not always host_mutation.** `from shutil import which; which(['pacman','-Q','hyprland'])`
   emits one `package_query / pacman:-Q` row at e629f73 (clean at 9c54c56) — the P family
   reaches every downstream classifier, not just sudo.
6. **`re.compile` is the lone clean pure import**, by collision with the builtin name in
   `PURE_ARG_CALLS` (`tools/mado-tripwire.py:1252-1257`), not by any stdlib knowledge.
7. **The same collision hides a real spawner.** `from webbrowser import open; open([...])`
   is exit 0 at e629f73 and at 9c54c56, though `webbrowser.open` is a browser launcher.
   `from webbrowser import open_new; open_new([...])` fires at e629f73 only. So a bare-name
   exemption cannot be applied after an import: the import rebinds the name (E3), and the
   binding — not the spelling — decides.

## Mechanism (source-observed, e629f73 bytes)

- `PURE_ARG_CALLS` is a flat set of 31 bare names with **no stdlib member in it at all**
  (`tools/mado-tripwire.py:1252-1257`); the module docstring's claim that "data calls
  (`print`, `json.dumps`, ...) are exempt (PURE_ARG_CALLS)" (line 47) is false for
  `json.dumps`.
- The lead dispatch fires for every bare `ast.Name` call whose lowercase dotted name is
  not in that set (`tools/mado-tripwire.py:1430-1433`) and passes each literal argv
  argument to `classify_shell` (`:1379-1390`).
- `ImportFrom` is canonicalized only for `subprocess`, `os` and `asyncio`
  (`tools/mado-tripwire.py:1346-1354`); a `from shlex import join` binding therefore stays
  a bare, unexempt name, and the literal list handed to it is classified as if it were a
  command line.
- Because the check is on the callee *spelling*, `from webbrowser import open` inherits the
  builtin `open` exemption, while `from re import compile` inherits `compile`.

## Spawn audit — which of the 17 modules can actually start a process

Method: token audit over the shipped 3.14.8 sources for
`subprocess|Popen|os.system|popen|fork|execv|spawn`, plus reading the public callable
bodies. Counts of 0: `collections/*.py`, `shlex.py`, `json/*.py`, `pprint.py`,
`textwrap.py`, `dataclasses.py`, `itertools` (C builtin), `operator.py`, `string/*.py`,
`enum.py`, `typing.py`, `re/*.py`, `pathlib/*.py`, `posixpath.py` (os.path), `shutil.py`,
`sys` (builtin; `dir(sys)` exposes no spawn API). `shutil.py`'s only `subprocess` hit is a
comment, and its imports are `os, sys, stat, fnmatch, collections, errno`
(`shutil.py:7-12`); `shutil.which` only walks `PATH` with `os.environ`/`os.access`/
`os.path` (`shutil.py:1561` onward, 0 spawn tokens in the body). `os.path` is `posixpath`
with 0 spawn tokens.

The only two modules of the 17 with a member that can carry a spawn are forwarding
primitives:

- `operator.call` — `return obj(*args, **kwargs)` (`operator.py:234-236`), so
  `call(os.system, 'sudo pacman -S foo')` runs it.
- `operator.methodcaller` — `return getattr(obj, self._name)(*self._args, **self._kwargs)`
  (`operator.py:310-330`), so `methodcaller('run', ['sudo','pacman','-S','foo'])(subprocess)`
  spawns with a literal argv list.
- `functools.partial` (C, imported at `functools.py:438`) and `functools.wraps` compose an
  arbitrary callable; `functools.reduce` (`functools.py:1163`) is also generic but takes
  the callable first, so the literal-argv path is `partial`/`wraps` (E2's existing
  carve-out).

Everything else in the 17 is process-free. Several are **not** side-effect-free, which
matters for E2's wording, not for the argv heuristic: `pathlib.Path.write_text/mkdir/
unlink`, `shutil.rmtree/copy/move`, `json.dump`, `pprint.pprint` write files/streams;
`sys.exit` raises; and `sys.remote_exec(pid, script)` (builtin, 3.14) executes a Python
file inside another process. None of them executes a literal argv list as a command, so
all are safe to exempt from the *argv-list* rule; none is "provably pure data".

## What the repair needs, from this evidence (advisory, not a design)

- Resolve the exemption on the **binding**: `from M import N` rebinds `N` (E3), so the
  callee is `(M, N)`. Allowlist whole modules — `collections, shlex, json, pprint,
  textwrap, dataclasses, itertools, string, enum, typing, re, pathlib, os.path, shutil,
  sys` — and carve out `functools.partial`/`wraps` (existing) plus `operator.methodcaller`
  and `operator.call`.
- Do not exempt a bare name after an import just because a builtin of that name is exempt:
  that is exactly what makes `from webbrowser import open` clean today.
- Keep the existing attribute path untouched: `M.N(...)` never reaches the lead branch, so
  no regression risk and no extra work there.
- Word E2's rationale as "cannot start a process and cannot forward the literal argv to
  one", not "provably pure": `sys.remote_exec`, `pathlib`, `shutil`, `json.dump` and
  `pprint.pprint` are all side-effecting while still being safe for this rule.

## Adjacent (do not misread a clean scan)

Documented argv shapes of two real spawners are *silently unparsed* at both revisions:
`from os import execvp; execvp('sudo', ['sudo','pacman','-S','foo'])` and
`from os import spawnlp; spawnlp(0, 'sudo','pacman','-S','foo')` each yield exit 0 with
`unparsed_spawns=1` (the `is_exec` branch at `tools/mado-tripwire.py:1420-1429` requires
all positional arguments to be strings). Conversely
`from asyncio import create_subprocess_exec; create_subprocess_exec('sudo','pacman','-S','foo')`
fires at both revisions. So an impure module scanning clean is not evidence of purity —
E2 decisions must come from the callable's semantics, as above.

## Limits

- Scan-only: `--scan` parse path only; no fixture executed, `--frozen`/`--selftest`, any
  suite, the lane gate or the live `mado-verify.sh` were not run. No counter (C1/C2) was
  invoked.
- One argv shape (`['sudo','pacman','-S','foo']`) for the matrix; a different argv would
  change the emitted rule, not the dispatch [INFERENCE from `helper_argv_leads` reading
  every positional argument].
- Host CPython 3.14.8 only; the module roster, `sys.remote_exec` and the source line
  numbers are version-specific. No other interpreter or PyPy checked.
- Spawn audit is a source token audit plus body reading over the shipped stdlib files; a
  dynamic `__import__('subprocess')` inside a pure module would evade the token scan
  [UNK]. Package audits were non-recursive within each package directory (`re/`, `json/`,
  `pathlib/`, `string/`, `collections/`).
- I did not test rebinding/shadowing (E3), decorators, lambdas, `del`, `reset` cells,
  help/dry-run (E4), or invisible-body leads (L); the cross-cell shape tested here is
  import-then-call only.
- Docs pages were not fetched; citations are the shipped 3.14.8 sources, which the library
  reference documents. No fetch receipts, because no web source was opened.
