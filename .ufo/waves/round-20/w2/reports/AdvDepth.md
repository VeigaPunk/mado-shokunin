## Starred / kw forwarding rules actually implemented

Works (row produced): `subprocess.run(*literal_list|tuple)`; `subprocess.run(**{"args": …})`;
`subprocess.run(args=…)`; `subprocess.run([*BASE, "x"])`; a `def h(*argv)` called with flat
literal strings; a `def h(**kw)` called with named keywords and forwarding `**kw` to
`subprocess.run`; `**kw` through 4 hops; literal tuple/list defaults (positional or
keyword-only); `functools.partial(subprocess.run, literal)` including `args=`; a visible
method; a nested `def`; an f-string call.

Fails with no row and no counter: any `*` in the argument list of a helper/method/class/
lambda call; any `**dict` at a helper call when the callee has no `**kw` (even an empty
`**{}`); `**kw` splat to a named parameter; a keyword-only parameter supplied through a
dict splat. Root: `bind_literal` returns `None` on any `starred` (`:1677`) and on a dict
splat without `**kw` (`:1697-1698`); `spawn_scan` then falls through to the bare `continue`
at `:1847` — no hit, no lead, no `unparsed`.

## Observed row naming a command that did not run (dict splat + default)

`Z-kwonly-default-via-dictsplat` and `Z-named-default-via-dictsplat`:

```python
def h(argv=("pacman", "-S", "other"), **kw):   # same for: def h(*, argv=(...), **kw)
    return subprocess.run(argv)
h(**{"argv": ["pacman", "-S", "advdepth-pkg"]})
```

The scan reports `host_mutation/pacman:-S`, `evidence: observed`, `command: "pacman -S other"`.
The command that runs is `pacman -S advdepth-pkg`. The dict splat is accepted into `**kw`
(`:1708-1713`) but its keys are never mapped to named parameters; the parameter is then
filled from its default (`:1717-1731`). If the default were benign, the real command would
be hidden behind a benign observed row. This is not silence but misattribution; both cases
are in `summary.json.wrong_argv`.

## Claims contradicted

1. `tools/mado-tripwire.py:35-37`: “A visible Python `def`/`async def`/lambda called with
   literal arguments is followed through its body up to four nested helper calls …”.
   Counterexample: `K-neg-star-helper-list` is a visible `def` called with a fully literal
   argument (`h(*["pacman","-S","advdepth-pkg"])`) and is not followed (no row, 0).
   `K-neg-kw-helper-no-kwarg` (`h(**{"argv": […]})`) is the same. `Y-immediate-lambda` is a
   lambda called with a literal argument and is not followed, and produces no lead either.
2. `corpus/knowledge/tripwire-precision-r20.md:88`: “A visible body is resolved to depth 4;
   `**kw`, starred and vararg forwarding are resolved only when the call states literal
   values.” Vararg and `**kw` forwarding do resolve when literal; **starred forwarding at a
   helper call never resolves, even when the call states a literal list/tuple**. The
   sentence is, at best, a necessary condition and reads as a bound that does not hold.
3. `tools/mado-tripwire.py:29-31`: “non-literal spawn arguments (counted as
   unparsed_spawns)” — in the paths above the spawn argument would be literal and the
   command reachable, yet `unparsed_spawns` stays 0. A `clean` verdict is not bounded by the
   blindnesses the limits section lists: the depth cutoff and bind refusals vanish with no
   machine-readable trace (no row, no `lead`, no counter).
4. QUALITY 30's `evidence: lead` marker does not cover these: a visible-helper bind failure
   produces no row at all, and star/dict-splat argv passed to an unresolved name produces no
   lead either (`C6`, `C7`), although the external body could execute it.
