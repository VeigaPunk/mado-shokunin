**5. Should any control have been stronger?** Findings, by severity:

- **F1 (LOW) — K1StaticBase is vacuous under this snapshot and subsumed by K1DoNothing.** The unperturbed base table is empty (`rules=0` on every receipt), so an honest StaticBase prints `[]` forever — byte-identical behavior to DoNothing, scoring exactly 1/41 (BASE) in all four versions (8 receipts). It can never discriminate anything unless the base snapshot gains rules. Not dishonest, but it burns two oracle runs per version while adding zero signal over DoNothing. Recommendation for future rounds: either give the base a nonempty table (out of scope for r27, snapshot frozen) or drop the control and say so.
- **F2 (LOW, population property) — the BASE case is structurally free for any `[]`-printer.** DoNothing/Echo/LabelKeyed/StaticBase/FlatScan all show `CASE BASE PASS rules=0` with `cases_pass=1/41`; the single pass is always BASE, so the discriminative population for C1 controls is effectively 40 cases. Disclosed by the receipts themselves; no action, but anyone reading `1/41` should know the 1 is structural.
- **F3 (LOW, informational) — K1FlatScan's variable pass is itself label-keyed on v1's fixture convention.** `K1FlatScan.py:29` substitutes only `$ws[a-z]{3}` — the name shape v1's generator used. That is part of why it reached 41/41 under v1 and why it collapses to 1/41 under v3/v4 random names. Consistent with its declared "source-blind v1 counterexample" role, but its variable handling is not a general reader and should not be cited as one.
- **F4 (LOW, provenance) — the v2 FlatScan pilot receipt was overwritten.** Registration first cites `controls/v2/K1FlatScan-L1pilot.txt` as 9/41 (unamended v2 counter), then, after the v2 amendment, cites the same path for the final-counter pilot at 1/41. The file on disk now shows counter sha `25811884…` and 1/41; the 9/41 bytes are not retained anywhere under `controls/`. Registration discloses both numbers, so nothing is hidden, but receipt paths should be append-only in future rounds.
- **F5 (LOW, residual risk) — seed variance is wide near the top.** Same-bytes score spread across seeds: FileScope 24 → 29 → 32/41; PrefixKeyed 16 → 17 → 15; GlobalOnce 18 → 17 → 17; NoMerge 20/7 (v2) → 14/8 (v3) → 7/9 (v4); NoVariables 20/16 (v1) → 17/9 (v2) → 7/1 (v4). v4's margin below the target is ~9 cases on its strongest control; a future round reusing v4 with new seeds should expect non-trivial score movement and pre-commit to how it will treat a control that crosses 41/41 post-data.

No MEDIUM or HIGH findings. Nothing in the receipts or sources undermines the controls-before-data gate: every registered control is present, honestly shaped, twice-seeded on the pinned counters, and all retirements are exactly the registered ones.

- C2 receipts (`K2*` in `controls/` and `controls/v2/`, `L1-sealed-rescore-summary.txt`) are outside this audit's scope; the v2 directory mixing C1 and C2 receipts is cosmetic.
