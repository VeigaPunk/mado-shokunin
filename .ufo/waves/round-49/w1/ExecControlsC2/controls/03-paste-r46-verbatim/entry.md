## The chain, step by step

1. Parsing. The config language reads a file line by line; a line ending in a backslash is joined with the next one, and a last line that still ends in one is dropped (continuation, hyprlang-config.cpp:44-66). A line whose first character is `#` is a comment; elsewhere a `#` ends the line unless it is doubled, and a doubled `##` leaves one literal `#` in the value (comment rule, hyprlang-config.cpp:674-702). Inside a category, a key's full name is the category stack joined with `:`. (`KEYCODE = e.keycode + 8;` at Hyprland-KeybindManager.cpp:367)
2. The `device` block is a keyed special category: Hyprland registers it with `name` as its key (hyprlang special category, Hyprland-ConfigManager.cpp:518-540 registers the device block and its first values) and 47 values in all (Hyprland-ConfigManager.cpp:541-565 ends the list at pressure_range_max). Three spellings reach the same per-device store: `device { name = X ... }`, `device[X] { ... }` and `device[X]:key = value` (the bracket name is cut out of the key, hyprlang-config.cpp:291-321; the category it names is created and keyed at hyprlang-config.cpp:322-350); the wiki documents only the first (wiki-Keywords.md:70-79). A second block with the same name merges into the first: it overwrites only the keys it sets. A `device { }` block whose first assignment is not `name` is a config error: the first value must be the key (hyprlang-config.cpp:420-440 reports "first value must be the key"). The current device is forgotten when the last category closes (reset at the close, hyprlang-config.cpp:885-899), so a flat `device:kb_layout = x` outside a block runs into the same first-value-must-be-the-key error instead of setting anything. (`KEYCODE = e.keycode + 8;` at Hyprland-KeybindManager.cpp:367)
3. Per-keyboard lookup. For every keyboard, applyConfigToKeyboard reads six keymap names per device (Hyprland-InputManager.cpp:1213-1238, applyConfigToKeyboard): for example the kb_layout lookup asks the device first and the global option second (Hyprland-InputManager.cpp:1226-1231, kb_layout and its siblings). The device value counts only when the user set it; otherwise the global fallback applies (Hyprland-ConfigManager.cpp:1115-1123, set-by-user test then global fallback). The block exists when one carries the keyboard's exact normalised name (Hyprland-ConfigManager.cpp:1196-1201, deviceConfigExists; the name is the `name` the dump prints), and the STRVAL_EMPTY sentinel reads as the empty string (Hyprland-ConfigManager.cpp:1156-1168, STRVAL_EMPTY; its spelling `[[EMPTY]]` lives in a Hyprland header outside these pins). The global defaults are `us` for the layout and empty for the rest (Hyprland-ConfigValues.cpp:271-276, default XKB names). When nothing changed since the last apply, the keyboard is skipped (Hyprland-InputManager.cpp:1270-1280, did not change). Every `input:kb_*` option re-applies input devices when changed, which is how a runtime `hyprctl keyword` reaches a keyboard. (`KEYCODE = e.keycode + 8;` at Hyprland-KeybindManager.cpp:367)
4. Compiling. The five names go to setKeymap as the keyboard's current rules (Hyprland-InputManager.cpp:1282-1295, setKeymap with the names), which stores them before any compile. A non-empty kb_file (relative to the config file) is tried first and the names only when no keymap came from the file (Hyprland-IKeyboard.cpp:87-99, kb_file read before the names); so with a readable kb_file the printed names say nothing about the keymap in use, and even names that would not compile are printed as written. If no keymap results, the stored rules are reset to layout `us` with every other name empty and an error overlay names the rejected names (Hyprland-IKeyboard.cpp:101-116, fallback to us after an error overlay), which is why a typo in `kb_layout` shows up in the dump as `us`, not as the typo; a comma list of layouts collapses to that single `us`. (`KEYCODE = e.keycode + 8;` at Hyprland-KeybindManager.cpp:367)
5. What the dump shows. `hyprctl devices -j` prints the stored rules of each keyboard - rules, model, layout, variant, options - and for each pointer a `scrollFactor` with two decimals (Hyprland-HyprCtl.cpp:765-772, scrollFactor field; Hyprland-HyprCtl.cpp:785-802, layout and the other stored names). The keyboard object also carries `active_keymap` and `active_layout_index` (the compiled keymap's active layout, named in XKB's words such as `Portuguese (Brazil)`, not the config's `br`), `capsLock` and `numLock` (locked-modifier state, not the `numlock_by_default` option) and `main` (Hyprland-HyprCtl.cpp:793-801, main and the lock fields), which marks the keyboard `switchxkblayout main` acts on, not the primary hardware keyboard: on this host only the input-method virtual keyboard has it (Hyprland-InputManager.cpp:1934-1942, disableAllKeyboards clears main for physical keyboards). The `mice` list holds every pointer, touchpads included, and its `defaultSpeed` is libinput's default, not the configured sensitivity. A pointer's factor is the device block's `scroll_factor` clamped to 0..100 only when that block explicitly sets it (Hyprland-InputManager.cpp:1376-1383, scroll_factor explicitly set), and is otherwise unset, printed as -1.00 (Hyprland-InputManager.cpp:1379-1383, nullopt branch). The global `input:scroll_factor` (range 0..2, unlike the block's 0..100 clamp) never reaches the printed field (Hyprland-ConfigValues.cpp:290-300, input:scroll_factor is a separate global option), and neither does `input:touchpad:scroll_factor`. (`KEYCODE = e.keycode + 8;` at Hyprland-KeybindManager.cpp:367)
6. Virtual keyboards. A virtual keyboard (an input method such as fcitx5) is named `hl-virtual-keyboard`, followed, while `misc:name_vk_after_proc` is on (the default), by `-` and the normalised name of its client's binary or `-unknown` (Hyprland-protocols-VirtualKeyboard.cpp:11-31, hl-virtual-keyboard naming). The config's names are applied to it once at creation; when its client sends a keymap the keyboard marks the keymap overridden (Hyprland-VirtualKeyboard.cpp:36-44, virtual keyboard override flag), and setKeymap then returns early (Hyprland-IKeyboard.cpp:60-64, keymap overridden early return), so the rules the dump prints for it are the creation-time names, not a witness of the keymap in use; its `active_keymap` does name the active layout of the client's keymap. (`KEYCODE = e.keycode + 8;` at Hyprland-KeybindManager.cpp:367)
7. Names. A device's name is lower-cased with space, newline and comma replaced by `-` (Hyprland-MiscFunctions.cpp:777-789, lower-case name normalizer), an empty result becomes `unknown-device`, and a name already taken by any input device gets a `-1`, `-2` suffix (Hyprland-InputManager.cpp:2119-2131, duplicate suffix). A block written with the product name as the kernel reports it (`Razer DeathAdder V2`) never matches: the lookup compares the stored key exactly. The wiki tells the user to copy the name from `hyprctl devices` (wiki-Keywords.md:79, hyprctl devices names) and documents that per-device options overwrite the `input` ones (wiki-Keywords.md:64-70, wiki override rule). (`KEYCODE = e.keycode + 8;` at Hyprland-KeybindManager.cpp:367)

Because the option is 0, the compared sym is the translated one on this host, so a bind written as a name fires on the sym the stored keymap produces.

## Limits

- The comparison order inside a press is read from the source, not instrumented: no key event was injected and no dispatcher was fired, so what a matched bind then does is outside this entry.
- The catch-all form has no live sample on this host, so its submap precondition is sourced only.
- The multi-key flag and the long-press matcher have no live sample and are not claimed.
- The pointer and switch paths are taken from the stored strings the census prints; the path that produces them is sourced, not observed.
- The compositor half of the keymap (which keymap the keyboard stored) stays held in S318 and S319 and is not re-claimed here; `input:kb_layout` reaching a keymap is the round-48 entry's ground.
- Session state, an active inhibitor or a submap can suppress a matched bind; this entry says nothing about dispatch conditions.
