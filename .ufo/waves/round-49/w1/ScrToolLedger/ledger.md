## Rules (all implemented in `check-ledger.py`)

1. **Instrument set** — every blob under `tools/` at the revision is either a row or a listed
   exclusion; the checker fails on a tool that is neither.
2. **Receipt** — a file which (a) sits under a `receipts/`, `evidence/` or `fetch/` directory or
   has `live` in its basename and (b) names the tool by basename or records one of the tool's
   committed digests. The bound receipt is the newest such file, by the committer date of the
   last commit touching it, that also carries the row's live marker and its verdict pattern.
   The two round-47 ledger seat directories are excluded by path: they quote other receipts.
3. **Verdict** — the one receipt line matching the row's pattern. A pattern that matches zero or
   two lines is a failure. A receipt that carries the tool's verdict but not the live marker
   (a selftest aggregate, a locator dump) can therefore never become the bound row.
4. **Bytes it ran** — the tool digest the receipt records, classified `current` (the bytes at the
   revision), `stale` (a committed earlier blob of the same tool) or `uncommitted` (no committed
   blob of the tool ever had it).
5. **Round** — `round-NN` from the receipt path, with the last-touch commit printed beside it.
6. **Newer live-named file** — the newest candidate with `live` in its basename, printed whenever
   it is not the bound receipt, so a later live run that lacks the tool's verdict line stays
   visible instead of hidden (round-47 H1b).

## Gate self-test (run by `check-ledger.py --emit` on every emit)

Each line mutates one field of the row data in memory; the derivation must then fail. A
`MISSED` line would mean the checker cannot falsify that claim, so it prints one here rather
than in a separate receipt.

- `CAUGHT` — question-line-out-of-range
- `CAUGHT` — verdict-pattern-matches-nothing
- `CAUGHT` — reads-literal-invented
- `CAUGHT` — class-literal-only-in-prose
- `CAUGHT` — receipt-marker-unsatisfiable
- `CAUGHT` — declared-token-invented
- `CAUGHT` — duplicate-row

## Limits

- A receipt is evidence that a run happened at those bytes, not that the host answers the same
  way now. No host probe was run for this ledger.
- `newest` is a path-and-commit-date rule over git objects. A live run recorded only in a seat's
  prose report, or in a file that neither names the tool nor records its digest, is outside it;
  each row prints its sweep size, so the boundary is auditable.
- `uncommitted` means the receipt records a digest no committed blob of the tool ever had: the
  bytes that ran were never the committed tool.
- The bound receipt is the newest receipt that carries the tool's own verdict line. A live run
  whose receipt omits that line (a census dump, say) is shown as the newer live-named file, not
  as the bound receipt.
