## 3. What the pinned source says, in the form a Python tool must reproduce

Line numbers are the `fetch/` ones (== the upstream file at the tag).

1. **ARG → keysym** (`how-to-type.c:286`–`299`): `xkb_keysym_from_name(arg, XKB_KEYSYM_NO_FLAGS)`;
   on `NoSymbol`, a base-10 `strtol` with `errno`/trailing-byte/`> XKB_KEYSYM_MAX` checks; on failure
   `ERROR: Failed to convert argument to keysym` on **stderr** and exit **2**.
   `from_name` itself (`keysym.c:237`–`350`) accepts, in order: a perfect-hash exact name match;
   `U<hex>` (and `u<hex>` only with the case flag); `0x<hex>` (and `0X<hex>` only with the flag),
   rejected above `XKB_KEYSYM_MAX`; and as a last ditch `XF86_<name>` with the underscore removed.
   Because `XKB_KEYSYM_NO_FLAGS` is passed, **the name lookup is case-SENSITIVE**.
2. **get_name** (`keysym.c:70`–`95`): `> XKB_KEYSYM_MAX` → `"Invalid"`, return −1 (how-to-type turns
   that into `ERROR: Failed to get name of keysym`); explicit table → one canonical name;
   `[0x01000100, 0x0110ffff]` → `U%04X` of the low 24 bits; otherwise `0x%08x`.
3. **mods_for_level** (`keymap.c:494`–`552`): wrap the layout into range; `level >= num_levels` → 0
   masks; for `level == 0`, if no active entry maps the empty mask to level 0 then `0` is offered
   first (this is the `[ ]` row); then one mask per active key-type entry with
   `entry->level == level`, bounded by `masks_size` (`MAX_TYPE_MAP_ENTRIES` from the caller).
4. **Row emission** (`how-to-type.c:527`–`536`, `635`–`702`): for `keycode` in
   `[min_keycode, max_keycode]`, skip keys with no name; for each layout of the key, for each level
   of the key, require `num_syms == 1` and `syms[0] == keysym` exactly; then print one row per mask:
   `printf("%-8u %-9s %-8u %-20s %-7u [ ", keycode, key_name, layout+1, layout_name, level+1)` then
   `printf("%s ", xkb_keymap_mod_get_name(keymap, mod))` for every mod whose `mask2` is fully
   contained in the mask, then `"]\n"`.
   Header: `printf("%-8s %-9s %-8s %-20s %-7s %-s\n", "KEYCODE", "KEY NAME", "LAYOUT",
   "LAYOUT NAME", "LEVEL#", "MODIFIERS")`. Prologue: `printf("keysym: %s (%#06"PRIx32")\n\n", …)`
   and `printf("=== Direct access ===\n\n")`.
   With `--disable-compose` the whole Compose section (`:599`, `:710`) is skipped, so stdout **ends
   with the last row's `]\n`** — no trailing blank line, no trailing section (measured: `od -c` tail
   of `receipts/judge/direct.out`).
5. **Keymap input**: `--keymap=FILE` → `xkb_keymap_new_from_file(ctx, f, DEFAULT_INPUT_KEYMAP_FORMAT,
   NO_FLAGS)` (`how-to-type.c:317`–`340`), and `src/keymap-formats.h` defines
   `DEFAULT_INPUT_KEYMAP_FORMAT XKB_KEYMAP_FORMAT_TEXT_V2`. The tool must therefore parse
   **XKB keymap text format v2**, which is exactly what `xkbcli compile-keymap` emits by default —
   the brief's "serialized by the pinned compile-keymap (default formats)" is this.

## 5. Corrections to facts stated in the round-49 brief (measured)

1. **"2659 `#define XKB_KEY_` lines" is a grep that counts comments.** The header has
   **2638** lines matching `^#define XKB_KEY_`; 21 further lines mention `define XKB_KEY_` inside
   comment blocks (e.g. `xkbcommon-keysyms.h:83`, `:124`, `:154`) — 2659 is `grep -c` over
   `define XKB_KEY_` anywhere. Measured in `receipts/sufficiency/analysis.txt`.
2. **Distinct values = 2505**, which is exactly `XKB_KEYSYM_COUNT_EXPLICIT 2505`
   (`fetch/keysym.h:41`) — a useful cross-check the brief did not have, and the reason the header is
   provably the whole explicit table rather than a superset.
3. **The host sample's row list is incomplete.** `--keysym slash` on `br` + `compose:caps` prints
   **five** rows (the `[ Lock … ]` and `[ Shift Lock … ]` combinations are there too). A counter that
   expects only the 3 level/mask groups named in the brief would fail against the real judge.
4. **Case matters, and the sample only works because the canonical name is lowercase.** `slash` is
   accepted (`XKB_KEY_slash 0x002f`, `fetch/xkbcommon-keysyms.h:646`); `SLASH`, `Return`'s
   lowercase `return`, `NoSymbol` and `U+0041` all exit 2. A C1 tool must be case-sensitive and must
   not set `XKB_KEYSYM_CASE_INSENSITIVE` "for friendliness".
5. **`NoSymbol` is a name in the header but an unusable ARG** (rc 2): `from_name` returns 0, which is
   also the failure sentinel, so how-to-type proceeds to the decimal fallback and fails.
6. **stderr is out of contract by necessity**: the usage text embeds `argv[0]`
   (`Usage: /usr/lib/xkbcommon/xkbcli-how-to-type …`, 2123 bytes). Only stdout + rc are comparable,
   exactly as the draft contract says.

## 6. Is `xkbcommon-keysyms.h` a sufficient data source? — measured answer: yes for names, with three rules beside it

Measured over the whole table (`receipts/sufficiency/`):

| measurement | result |
|---|---|
| `^#define XKB_KEY_` lines | 2638 (`val-name.txt`) |
| distinct numeric values | 2505 == `XKB_KEYSYM_COUNT_EXPLICIT` |
| values with >1 name (alias groups) | 120 |
| canonical name == **first** define of that value in header order | **120 / 120** |
| canonical name == last define | 0 / 120 |
| canonical name == neither end | 0 / 120 |
| header names asked of the judge as `--keysym <name>` | 2638 |
| accepted and naming their own value | **2637** |
| rejected | 1 — `NoSymbol` (rc 2) |

Method: for every defined value the judge was asked `--keysym 0x<value>`; line 1 is
`xkb_keysym_get_name(value)`, so the judge itself is the oracle for canonicality (`oracle.tsv`).
Then every defined name was asked back (`name-roundtrip.tsv`).

**Verdict.** A table generated *from the header alone* is sufficient — but only together with three
rules that are not in the header:

1. canonical name for a value = **its first `#define` in header order** (holds for all 120 alias
   groups; e.g. `0xff55` → `Prior`, not `Page_Up`; `0xffc8` → `F11`, not `L1`; `0xfe53` →
   `dead_tilde`, not `dead_perispomeni`);
2. `get_name`'s two non-table branches: `[0x01000100, 0x0110ffff]` → `U%04X`, else `0x%08x`
   (measured: `0x01000100`→`U0100`, `0x012345`→`0x00012345`, `0x200000`→`0x00200000`,
   `0x1fffffff`→`0x1fffffff`, and `> 0x1fffffff` is rejected on input);
3. `from_name`'s non-table branches: `U<hex>`, `0x<hex>`, decimal, and the `XF86_` strip — all
   case-sensitive; and the `NoSymbol` == 0 trap.

The header marks deprecated aliases **only in comments** (`X2` `xkbcommon-keysyms.h:265`:
`/* deprecated alias for Prior */`), so a tool must not try to read canonicality from comment text;
line order is the rule, and it is stable because both the header and the library's
`keysym_to_name`/`name_to_keysym` tables are generated from the same definitions
(`KH5` `keysym.h:2`: the header is "generated automatically by" a script, i.e. header order and the library's canonical table come from one source).

One caveat worth stating in the tool's docstring: this "first define wins" rule is an observed
property of this pinned header, not a documented guarantee of libxkbcommon. The C1 counter should
pin the header digest (already in the brief) so the rule cannot silently drift.

## 7. Risks / traps for the C1 counter (all grounded above)

- **Sandbox seam**: the tool must open the keymap file and nothing else *if* the names table is
  embedded — but the contract as drafted lets it read the keysyms header. If the header is allowed,
  the sandbox must expose it; if the table is embedded, the header need not be mounted. Either way
  the *counter* must not let the tool exec `xkbcli` (the brief's "no process").
- **`mask2 == 0` trap** (`T5`, `how-to-type.c:531`): the containment test is
  `if ((mask & mod_mask) != mod_mask) continue;`, so a modifier whose `mask2` is 0 passes the test
  on **every** row and its name is printed unconditionally. No such modifier appeared in the six
  RMLVO combinations I compiled (`us`, `br`+`compose:caps`, `us`+`lv5:lsgt_switch`, `us`+`ctrl:nocaps`,
  `us,br`+`grp:alt_shift_toggle`, `fr`), so it is unobserved on the fixture space — but a
  reimplementation that prints "names whose bits are set" is *not* equivalent to the C source in
  that corner. Flagging, not asserting reachability from xkeyboard-config 2.48 RMLVO.
- **Locale**: `setlocale(LC_ALL, "")` runs, but with `--disable-compose` no Compose table is loaded and
  names are ASCII, so output does not depend on `LC_ALL` (the receipts were produced under
  `LC_ALL=C.UTF-8` and the `env -i` runs carry no locale env at all).
- **Keymap parse scope**: the tool needs XKB text-format-v2 parsing (keycodes/symbols/types/
  compat/virtual_modifiers), i.e. `xkb_keymap_key_get_syms_by_level` and
  `xkb_keymap_num_levels_for_key` equivalents plus key-type resolution. It cannot be done from the
  keysyms header alone; §3.5 is the citation for *why* the input is v2 text.
- **stderr/argv[0]**: never compare stderr. `T17` shows the message, but the usage block names the
  judge's own path.
