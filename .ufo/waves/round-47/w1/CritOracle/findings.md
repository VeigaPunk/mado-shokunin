# CritOracle — findings: real-script-as-judge robustness (C1)

Target: pinned judge = `/usr/bin/xdg-terminal-exec` (sha256 `89f2be9a65deb8df93633a9a09b4953a921c83d591ab987f7569280ecd3127ac`, v0.14.3, 1499 lines, POSIX sh; this host: `/bin/sh`→bash, gawk 5.4.1, GNU findutils, GNU coreutils tr). Method: controlled runs on `/fast/scratch/hyaku/mado-r47/CritOracle` (xfs), inside bubblewrap, strace -f, `env -i` with pinned variables; receipts: `execve-cold.log`, `execve-warm.log` (this dir).

## F1 — fallback selection order = `find -L` readdir order (unsorted) -> content-identical fixtures can pick different terminals
Repro (creation order flip, identical file contents):
```
C=$S/e2e/t1   # S=/fast/scratch/hyaku/mado-r47/CritOracle
# a.desktop & b.desktop both valid TerminalEmulator, Exec=alacritty/kitty stubs on PATH
# order A,B: cp a.desktop; cp b.desktop into applications dir
env -i HOME=$C/home PATH=$C/bin:/usr/bin:/usr/sbin XDG_CONFIG_HOME=$C/home/.config \
  XDG_CONFIG_DIRS=$C/root XDG_DATA_HOME=$C/home/.local/share XDG_DATA_DIRS=$C/root \
  XDG_CURRENT_DESKTOP=Hyprland XDG_CACHE_HOME=$C/home/.cache LC_ALL=C \
  /usr/bin/xdg-terminal-exec --print-id --print-path --print-cmd
# -> b.desktop ... /kitty (rc 0)
# recreate applications dir in order B,A (cp b.desktop; cp a.desktop) -> a.desktop ... alacritty
```
Evidence: t1 (order A,B) selected `b.desktop`; t2 (order B,A) selected `a.desktop`; t3 repeated A,B → b.desktop again (reproducible per materialization).
Cause: `find_entry_paths` emits paths via `LC_ALL=C find -L "$@" 2> /dev/null | awk '{ print; sub(".*/[.]/", ""); gsub("/", "-"); print }'` (`/usr/bin/xdg-terminal-exec:795-797`); output is never sorted (no `sort` anywhere in the script), so the fallback list `XTE__FALLBACK_ENTRY_IDS` is built in readdir order (`:790`); `find_entry` walks it in that order (`:1060`). Directory traversal order is filesystem-defined: small xfs dirs returned insertion order (observed), a 400-file xfs dir returned neither insertion nor sorted order (`:` readdir != insertion, DIFFERENT). Different FS types (btrfs/ext4/tmpfs), or same FS with different creation history, yield different winners.
Impacts: byte-identity between judge and tool cannot be guaranteed for fixtures with >1 co-equal candidate in one applications dir unless materialization order is pinned. `expect` being generated by running the real script on the materialized case masks this per-run but does not remove run-to-run divergence if build order changes.
Smallest safe correction:
- Fixture driver MUST create files in a canonical order (e.g., sorted by root-relative path) and ban ambiguous cases: at most one surviving candidate per applications dir, or pin selection via `xdg-terminals.list` IDs (list order is definitional, `:351-475`).
- Keep `expect` generated from the materialized case as prescribed (ground truth), but the generator must use the same canonical creation order every time.

## F2 — sandbox without `/dev` silently breaks selection (missing `/dev/null` → rc=1 NO_TERMINAL even with valid terminals)
Repro V2 (no dev mounts):
```
bwrap --ro-bind /usr /usr --ro-bind /etc /etc --ro-bind /lib64 /lib64 \
  --bind /bin /bin --proc /proc --bind $C/home /home --bind $C/bin /bin2 \
  --chdir /home --unshare-all --die-with-parent /usr/bin/bash -c '... script ...'
# -> stderr: line 200/199/756: /dev/null: No such file or directory
# -> "No valid terminal entry was found in: ..." rc=1
```
With `--dev /dev` (fresh dev tmpfs incl. null), the same case works: rc=0, correct entry. Cause: the script redirects to `/dev/null` at `:200` (`ls -LRl ... 2> /dev/null`), `:795` (`find ... 2> /dev/null`), and `:756` (find entry path loop); redirection open failure aborts those commands, so `find` never runs and no entries register. Additional required mounts: /proc (`--proc`), /bin (shebang `#!/bin/sh` — `/bin` is a symlink to `/usr/bin` on this host; without it, `execvp` of the script's interpreter fails), /lib64 (dynamic loader; bare `/usr` bind fails with `execvp /usr/bin/bash: No such file or directory`).
Smallest safe correction (sandbox recipe):
```
bwrap --unshare-all --proc /proc --dev /dev --tmpfs /tmp \
  --ro-bind /usr /usr --ro-bind /lib64 /lib64 --ro-bind /etc /etc \
  --bind /bin /bin --bind "$ROOT" "$ROOT" --chdir "$ROOT" --die-with-parent ...
```
Do NOT use `--ro-bind / /`: it exposes host data/config trees (see F3, F8). Pin `LC_ALL=C LANG=C` in the sandbox env (also prevents the script's self-respawn, F5).

## F3 — unset XDG_* keys leak HOST state into the decision (defaults point at host trees)
Repro: fixture omits XDG_DATA_DIRS/XDG_CONFIG_DIRS (schema marks absent = unset):
```
env -i HOME=$C/home PATH=$C/bin:/usr/bin:/usr/sbin XDG_CONFIG_HOME=$C/home/.config \
  XDG_DATA_HOME=$C/home/.local/share XDG_CURRENT_DESKTOP=Hyprland \
  XDG_CACHE_HOME=$C/home/.cache LC_ALL=C /usr/bin/xdg-terminal-exec --print-id --print-path --print-cmd
# -> Alacritty.desktop /usr/share/applications/Alacritty.desktop alacritty rc=0
```
On this host `/usr/share/xdg-terminal-exec/xdg-terminals.list` exists (1053 bytes) and `/usr/share/applications/` has 121 entries — the decision then reflects host content and host readdir order. Cause: `${XDG_DATA_DIRS:-/usr/local/share:/usr/share}` and `${XDG_CONFIG_DIRS:-/etc/xdg}` defaults (`:148,157,166`).
Smallest safe correction: fixture schema must make all four XDG keys REQUIRED (`XDG_CONFIG_HOME`, `XDG_CONFIG_DIRS`, `XDG_DATA_HOME`, `XDG_DATA_DIRS`), and the driver must assert presence; HOME=$ROOT/home stays fixed.

## F4 — cache: warm-cache short-circuit + cross-case state leakage
The cache (`$XDG_CACHE_HOME/xdg-terminal-exec`, `:172-173`) is validated by hashing `echo 4` + XDG_CURRENT_DESKTOP + `LANG=C ls -LRl` of config/data paths piped into `md5sum` (`:189-203`). Hash covers only those trees — not PATH, not executable contents. Consequences:
- Warm run reuses prior selected entry without re-scanning (`read_cache`, `:221-298`); warm execve set differs from cold (F5).
- If two cases share the same `XDG_CACHE_HOME` and identical config/data trees (hash equal, cached command still found by `command -v`, `:274`), the second case inherits the first's cached selection even if ambient PATH/stubs changed — stale results.
- Cache save happens in a backgrounded subshell (`save_cache "$1" &`, `:1457`); under `--die-with-parent` it is killed before writing. `XDG_CACHE_HOME` with unwritable parent: rc still 0 (observed), failure silent.
Smallest safe correction: per-case fresh cache dir (e.g., `XDG_CACHE_HOME=$ROOT/.cache` created just before each run, removed after); never reuse across cases. Contract already models cold cache — keep the judge cold by construction.

## F5 — external-tool set differs by cache state; tripwire must not wrap the judge
strace -f execve counts (cold vs warm, same fixture):
- cold: `xdg-terminal-exec`, `find`, `awk`, `tr`;
- warm (valid cache): `xdg-terminal-exec`, `ls`, `md5sum`, `tr`.
Additionally, each of `gen_hash`/`read_config_paths`/`read_entry_path` re-executes the script with `LC_ALL=C` when `LC_ALL` != C (`:185,357,974`) — an extra self-spawn under non-C locales. The C1 tripwire (strace execve count; fake binaries bound over `/usr/bin/xdg-terminal-exec` and the shells) must therefore be scoped to the TOOL's process subtree: the judge legitimately spawns the above. Binding a fake `/bin/sh` over the real one changes the judge's interpreter (shebang `#!/bin/sh` → bash in POSIX mode), which can alter behavior (e.g., ENV/BASH_ENV handling, signal propagation, `set -euf` nuances). Fix: attach tripwire by PID ancestry from the tool (not the judge); if shell wrapping is needed, it must exec the real sh transparently; pin LC_ALL=C to suppress self-respawn.

## F6 — locale: `tr` lowercasing is ASCII-only under every installed locale (verified); still pin LC_ALL=C
`XTE__LOWERCASE_XDG_CURRENT_DESKTOP=$(printf '%s' "${XDG_CURRENT_DESKTOP-}" | tr '[:upper:]' '[:lower:]')` (`:1144`). Test: `printf 'ÉCOLE\n' | tr '[:upper:]' '[:lower:]'` under `C`, `C.utf8`, `en_US.utf8` all emit `c3 89 63 6f 6c 65 0a` (É unchanged) — no divergence today. Note the script forces `LC_ALL=C` for find/hash/entry parsing (`:795,200,185,357,974`), so the only ambient-locale-sensitive byte is this `tr`. Pin `LC_ALL=C LANG=C` anyway (matches script-internal forcing; guards future glibc/coreutils behavior; avoids F5 self-respawn). Tokenizer bracket class `[[:space:]]` (`:573`) is the same in C; exotic UTF-8 whitespace in Des would make the tool's Python reimplementation diverge — keep fixtures ASCII.

## F7 — awk: single use, portable, same binary in sandbox
Only `:797` uses awk (`sub`/`gsub` on path→ID). gawk 5.4.1 host binary is reachable via the `/usr` bind. Low risk; but the harness must bind `/usr` (or at least `/usr/bin`, `/usr/lib`) so `find`/`awk`/`tr`/`ls`/`md5sum` resolve to the identical host binaries. Cross-host (busybox/toybox) would change behaviors (incl. `find -L` loop diagnostics wording) — irrelevant inside one sandbox but relevant to any claim of host-equivalence.

## F8 — symlinks: `find -L` follows them; loop detection ok; containment required
`find -L` on a cycle prints `filesystem loop detected` (stderr, silenced) and does not recurse — no hang (observed). But `-L` also follows *file* symlinks: a fixture `evil.desktop -> /etc/passwd` matches `-path` and `-type f`, and is then read as a desktop entry (`read_entry_path`, `:970-1018`). With `--ro-bind / /` the fixture can therefore reach host files; without it, only bound dirs are reachable. Fix: driver must not materialize symlinks (schema: `files` values are text; ban `symlink` entries) and the sandbox must use explicit dir binds (F2 recipe), not the whole host root.

## F9 — argv0, stderr, SIGPIPE, exit codes
- `$0` appears only in usage/help text (`XTE__SELF_NAME=${0##*/}`, `:32`), printed only for `-h/--help` (`:1136-1139`); unknown options are silently discarded (`:1317-1320`) with no usage error. Print modes never emit `$0`, so argv0 differences cannot reach stdout.
- stderr is out of contract but is noisy: `No valid terminal entry was found in:` (with each dir on its own line, `:1109`), `Assuming '…' means no` (`:55`), `/dev/null` redirection errors (F2). Harness must compare stdout + rc only.
- Exit codes observed: success 0; NO_TERMINAL 1 (`find_entry || exit 1`, `:1208`) with empty stdout; help 0. The tool's print mode must reproduce rc=1 for no-terminal (the explain-mode code 3 must not leak into print mode).
- SIGPIPE: tiny outputs never hit EPIPE (pipe buffer absorbs; observed `PIPESTATUS=0 0` with `head -c 1`); only multi-64KiB `--print-cmd` output truncated by a closed reader would kill the writer with rc 141. Harness reads to EOF, so not reachable.

## F10 — duplicate IDs across data dirs are deterministic (user override wins)
`make_paths` builds applications dirs system-first, datahome-last (`:166-169`); `find` visits operands in that order and "last found wins" per ID (alias overwrite, `:779-792`). Verified: `z.desktop` in `/usr/share/applications` (Exec=kitty) vs `$XDG_DATA_HOME/applications/z.desktop` (Exec=alacritty) → selected `z.desktop` user path, `alacritty`, rc 0. Matches the L1 host fact (user override wins). No action; do not "fix" this by sorting.

## F11 — XDG var parsing is positional and deterministic
`IFS=':'` splitting includes empty segments (e.g., `XDG_DATA_DIRS=:/usr/share` produces an empty dir → `applications/` fallback). Deterministic; the tool must replicate IFS splitting exactly, including empty segments and trailing-slash normalization (`%/`, `:148-169`).
