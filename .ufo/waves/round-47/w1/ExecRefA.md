agent shell (peer warning) is irrelevant here: the dict replaces the whole environment.

## 1. Method

1. Read all 1499 lines of the script, then wrote the model branch by branch with `xte:NNN` citations
   computed by `grep -n`.
2. Built `cmp.py`: materialise a case (files + 0755 script stubs + dirs), run the real script and the tool

3. Four generators, then everything that disagreed was turned into a finding (section 2) and either fixed

## 2. Findings — every disagreement my first model had with the script

Each one was found by a failing comparison, then located in the script. All are fixed in the tool.
These are the parts a reference implementation *will* get wrong if it models the spec instead of the code.

**F1 — `Exec` tokenizer/field-stripper failures are NOT fatal (xte:956-962).**
`de_tokenize_exec` and `de_strip_fields` are called without `|| return 1`, so their `return 1` only sets
`$?`. The partially accumulated `XTE__EXEC_USEP` survives (`de_strip_fields` fails *before* assigning), and
only `command -v "$XTE__EXEC0"` gates the entry. Observed: `Exec=sh | cat` → stdout `sh` (rc 0);
`Exec=sh %z` → stdout args `sh`, `%z` (rc 0). First disagreed on my cases 15 and 52; now modelled including
the `\x1f`-separated residue.

**F2 — `-type f` only guards the FIRST find operand (xte:755-773).**
The argv is `dir1/. dir2/. … -type f ( cond1 ) -o ( cond2 ) -o ( cond3 )`, which parses as
`(-type f && cond1) || cond2 || cond3`. So in every applications dir except the lowest-preference one, a
**directory** named `*.desktop` is matched and registered. Reading it then fails (`done < "$path"`), `set -e`
kills the script: **rc 1, empty stdout**. Verified: `find` printed `apps2/./Dir.desktop` for a directory.
First disagreed on designed case 49 and on the `wild` case that materialised `dir.desktop/`.

**F3 — `IFS` leaks out of `check_entry_key`'s show-in loops (xte:846-887) and changes the diagnostic.**
`IFS=';'` before the loop, `IFS=':'` inside, restored only *inside* the inner body. If `XDG_CURRENT_DESKTOP`
is empty the inner loop never runs and `IFS=':'` is left set; if the value has no fields, `IFS=';'` is left
set. Only observable in `IFS=':' error … ${XTE__APPLICATIONS_DIRS}` (xte:1109), where the colon-joined list
splits into one line per directory **only** in that case. Reproduced hermetically: same fixture, with and
without `XDG_CURRENT_DESKTOP`, gives one-line vs two-line stderr. Modelled (`Resolver.ifs`).

**F4 — an empty argv word before `--` makes the real script spin forever (xte:1277-1394).**
The `case "$1" in` arms cover `--`, `-e`/EXECARG, the `--*` options, `[!-]*` and `-*`. The empty string
matches none of them and there is no `shift` on that path, so `while [ "$#" -gt 0 ]` never terminates.
Verified: `xdg-terminal-exec --print-id ''` → `timeout` rc 124; `… '' -e x` → 124; `… --print-id -- ''` → 0
(the `--` breaks first). This is a live operability defect: a wrapper that passes an empty argument hangs the
hotkey. The tool cannot hang, so it exits **4** with a stderr note, and the harness counts
(theirs=TIMEOUT, ours=4) as the modelled outcome.

**F5 — residue: `EXEC_USEP` and `IS_TERMINAL` are not reset when `find_entry` rejects post-hoc (xte:1086-1100).**
`reset_keys` runs only on a key-level discard. An entry that reads cleanly but has no `Exec` leaves
`IS_TERMINAL` set for the next candidate, and one with no `Categories` leaves `EXEC_USEP` set. Observed
(case `48-residue`): `aaa` has `Categories` only, `bbb` has `Exec` only; the fallback order tries `bbb` first,
so `bbb`'s `Exec=alacritty` survives into `aaa`, and the script selects **aaa.desktop** with command
`alacritty`. My first model rejected both.

**F6 — a final line without a trailing newline is invisible (`while read`).**
`Exec=sh` as the last line with no `\n` is never read (case `d11`, rc 1). Same for list files: a list whose
last line lacks `\n` loses that line.

**F7 — the desktop-entry key dispatch is a prefix match + "contains =" (xte:802-968).**
The patterns are `'Categories'*=*`, `'Exec'*=*`, …, so `ExecArg=-x` is treated as `Exec` (last match), and
`CategoriesX=…` as `Categories`. A line with no `=` matches nothing and is silently ignored.

**F8 — `Hidden` is only the literal `true` (xte:938-946).** `Hidden=True`, `Hidden=1`, `Hidden=false` all pass.
**F9 — `Type=` and `NoDisplay=` are never read at all.** Confirmed independently by peer ScrSkill-2 (probes A/B)
and by my cases 20/`20-nodisplay-type`; `Type=Link` + `NoDisplay=true` is selected. `explain` says so in a
header line and never invents a "wrong Type" rejection.
**F10 — ID precedence and single-attempt IDs (xte:754-800).** `make_paths` *prepends* applications dirs
(xte:143-177), find walks lowest-preference-first, and each registration overwrites the alias, so the user dir
wins — the spec's "first wins" in preference order, the opposite of find order. `unalias` after the first
attempt means an ID listed twice is tried once.
**F11 — `--print-path` collapses `/./` as first-prefix + last-suffix (xte:1403-1406)** and mutates
`XTE__ENTRY_PATH`, so `--print-content` afterwards reads the collapsed path.
**F12 — `read` strips exactly one trailing delimiter.** `IFS='=' read -r a b` on `--k=x=` gives `x`;
`--k=x==` gives `x==`; `IFS=':' read -r a b c` on `a:b:` gives `c=''`. Matters for `--print-delimiter=` values
ending in `=` and for list lines like `foo.desktop:New:`.
**F13 — `-h`/`--help` anywhere before `--` wins before any path work (xte:1168-1178)**, and the help text
contains the script's own basename, so the tool must print `xdg-terminal-exec` there.
**F14 — list-line validation is a shell glob, and failures are loud (xte:399-465, 1020-1053).** `+`/`-` alone,
`bad name.desktop`, `sub/ccc.desktop` are "Discarded possibly misspelled entry '<line>'" on stderr (modelled),
while comments, blanks and `/unknown/directive` are silent.

## 4. Freeze input for the C1 counter (what will bite a naive judge)

1. **Never run the reference without a print mode.** `xdg-terminal-exec` with no `--print-*`/`--test`
   *launches a terminal*. Every fixture must carry `--print-id`, `--print-path`, `--print-cmd[=…]`,
   `--print-content` or `--test`.
2. **Exclude or special-case the empty argument** (`""` before `--`): the reference hangs, so no rc exists to
   compare. My tool's rc 4 is a refusal, not a modelled value.
3. **Invoke the tool with an absolute interpreter** (`/usr/bin/python3 tools/mado-terminal.py print …`).
   With `env -i` and a fixture PATH, a bare `python3` is not found; and if python3 is put on the fixture PATH it
   becomes visible to `command -v` on *both* sides.
4. **Tripwire shape.** `strace -f -e trace=execve` on `python3 tool print …` gives exactly **1** execve (the
   interpreter image; receipts/strace-print.txt). Run through the shebang, `/usr/bin/env` adds 12 failing
   `execve` probes on this host (PATH search) — count only **successful** execve, or forbid execve whose target
   is `xdg-terminal-exec`/`sh`/`bash`/`dash`/any shell, otherwise the tripwire fires on a clean tool.
   Socket audit: 0 `socket`/`connect` calls; 0 write-mode opens in print mode (receipts/strace-*.txt).
5. **Compare bytes, not text**: `--print-delimiter='\0'` puts NULs on stdout (bash `printf '%b'`).
   Also `\c` truncates one printf, `\x4` is 0x04, `\0101` is `A` — `printf_b()` implements bash's `%b`.
6. **Fresh empty cache dir per invocation on the reference side**; `md5` of `ls -LRl` means size+mtime only, so
   a warm cache can return a stale answer.

## 7. Risks / open items for w2

- The model follows `sh` = bash in POSIX mode (this host). On a host where `/bin/sh` is dash, `command -v`
  and `read` edge cases (F12) could differ; the tool's `command -v` implements the bash-POSIX rule
  (regular file + x bit), which is what the pinned host does.
- Locale: `tr '[:upper:]' '[:lower:]'` for the list prefix is modelled ASCII-only (xte:1183). A non-ASCII
  `XDG_CURRENT_DESKTOP` would diverge; no fixture uses one.
- `IFS` inherited from the caller (exported `IFS`) would change `read` trimming in the real script; not modelled.
- The selftest's 52 cases only use `sh`/`alacritty` stubs, so they are PATH-hermetic by construction; adding a
  case whose Exec is `tr`/`find`/`awk` would make the selftest depend on the sandbox tool bin.
