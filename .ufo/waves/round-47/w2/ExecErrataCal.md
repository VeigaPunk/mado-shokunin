## 6. Holes and context notes (H1-H7)

**H1 — E1's "minted after load" has no command behind it, and history cannot supply one.** All three texts —
the `LOG.md:2499` line ("Mistakes M44-1..7"), M44-8 and M44-9 — enter the repository in the *same* commit:

```
$ git log -S 'Mistakes M44-1..7' --oneline -- LOG.md            → e4678921 (one commit)
$ git log -S '**M44-8' --oneline -- corpus/lessons/round-44.md  → e4678921 (one commit)
```
So `git log -S` gives no ordering, and the appended E1 line asserts a sequence it does not evidence. The proof
exists one directory over and the errata never cites it: the round-44 lesson skeleton (the pre-data draft) says
`mines them as Mistakes M44-1..M44-7`
(`.ufo/waves/round-44/w1/ScrLessonSkeleton/round-44-lesson.md:6`), and that same draft file already carries
**8** `**M44-` headers (M44-1…M44-8) while the integrated lesson carries 9 — so the load-time count was 7,
M44-8 was minted during `w1`, and M44-9 at integration. Add to the E1 line:

```
$ git show HEAD:.ufo/waves/round-44/w1/ScrLessonSkeleton/round-44-lesson.md | sed -n '6p'   # "... M44-1..M44-7 ..."
$ git show HEAD:.ufo/waves/round-44/w1/ScrLessonSkeleton/round-44-lesson.md | grep -c '^\*\*M44-'   # 8
```
(`e1-loadtime.txt`.) Without it a w2 reader can only verify "the LOG says 7 and the lesson says 9", not "7 was
the load-time count".

**H3 — E2's "QUALITY 83 class, one directory up" is not what the published check reports.** Run on the same
document at the data commit, criterion 83's check never sees the citation, for two independent reasons:

- its token regex admits only a fixed extension list that omits `tsv` (`check83.py:25`,

  `assimilation/renumber-map.tsv` is never extracted — it does not appear in the output in either mode;
- even a `.tsv`-admitting token would be dropped by the prefix filter at `check83.py:93`
  (`if a.prefix and not tok.startswith(a.prefix)`), because the lesson writes it bare while the published
  invocation passes `--prefix .ufo/`.

The run lists 13 citations with and 84 without the prefix, and `assimilation/renumber-map.tsv` appears in
neither; so the class label is an analogy, not a violation the criterion can produce. Either drop it or state it
as "a path-resolution defect of the same kind, which the published check cannot see — its extension list has no
`tsv` and its prefix filter skips bare tokens" (`e6-criterion83-run.txt`).
