  aliases line "inode/directory application/x-customalias"
      -> a directory answers application/x-customalias (not inode/directory)
  aliases line "application/x-zerosize application/x-weird"
      -> a 0-byte file answers application/x-weird

  inode/blockdevice, inode/fifo, inode/socket and application/x-zerosize are

  reading holds for the host's own database.

    TABLE IS APPLIED. THIS CONTRADICTS DECLARATION RULE 1.
    Declaration bytes: "every one of these is returned through
    `g_content_type_from_mime_type`, which is the identity on Unix

    Source bytes (A8): g_content_type_from_mime_type (gcontenttype.c:290-296)
    forwards to g_content_type_from_mime_type_impl (A:551) which returns
    xdg_mime_unalias_mime_type (A:560); xdgmime.c:735-746 resolves that
    through the alias table (cache_alias_lookup in cache mode, the aliases

    but a frozen C1 case whose mime tree carries an aliases file would
    disagree with a candidate that hard-codes the inode/* strings.
    The alias rewrite is NOT applied to the name-only guess (a .txt file
    still answers text/plain under an alias line "text/plain
    application/x-textalias").

D6  A SYMLINK LOOP IS NOT A STAT FAILURE: GIO ANSWERS inode/symlink WITH
    EXIT STATUS 0. THE DECLARATION PUTS IT IN THE ERROR CLASS.
    Declaration bytes (rule 7): "a path that cannot be stat'ed at all
    (missing, or a symlink loop) is outside the surface: the tool prints
    `MADO_FILETYPE: ERROR stat` for that path and exits 2 (the same refusal
    `gio info` makes)".
    Measured, twice, with two independent 2-cycles:
      gio info -a standard::content-type ./z1   (z1->z2->z1)
        attributes: / standard::content-type: inode/symlink ; exit status 0
      gio info -a standard::content-type ./l1   (l1<->l2)
        attributes: / standard::content-type: inode/symlink ; exit status 0
    Source reason: lstat on the link itself succeeds (glocalfileinfo.c:1932),
    so is_symlink is TRUE (B:1964) and the follow-stat fails with ELOOP, which
    sets symlink_broken (B:1993-1994); the first branch then answers
    inode/symlink (B:1308-1310). A missing path, by contrast, does make gio
    exit 2 with no attribute (measured).
    Impact: the case-file label rule (ERROR only when gio exits non-zero and
    prints no attribute) plus this measurement puts symlink loops in the
    inode/symlink class, not the ERROR class; a candidate that answers
    ERROR stat for a loop would be scored wrong on such a case.

D7  THE SNIFF-LENGTH CLAMP IS "0 OR GREATER THAN 16384", NOT "0 OR LARGER".
    Declaration bytes (rule 4): "the sniff length: ... clamped to 16384 when 0
    or larger (`glocalfileinfo.c:1352-1355`)"; the seat contract says
    "0 or > 16384 -> 16384".
    Source bytes (B3): B:1354 "if (sniff_length == 0 || sniff_length > sizeof
    (sniff_buffer))" and B:1355 "sniff_length = sizeof (sniff_buffer);" -
    sizeof(sniff_buffer) is 16384 (B:1346). A length between 1 and 16384 is
    used as it stands and is NOT raised to 16384.
    Measured on this host: the cache's MAX_EXTENT is 18730, so the clamp does
    fire here (effective length 16384); the distinction still matters for any
    case whose database declares a smaller extent.
    The cited range is also off: the call is at 1353 and the clamp at
    1354-1355 (1352 is blank).

D8  THE gio(1) MANUAL NAMES NO CONTENT-TYPE ATTRIBUTE, AND NO VERSION; THE
    S527 SCOPE MUST BE THE CLI CONTRACT ONLY.
    Measured on the decompressed 781-line text:
      grep -c "content-type" -> 0 ; grep -c "fast-content" -> 0
      grep -n "standard::"  -> 200, 244, 661, all standard::icon
      .TH line C:31 is .TH "gio" "" "" ""   (no version, no date)
    So the row may claim: the info command and its options (-a/--attributes,
    -n/--nofollow-symlinks), and the exit status sentence. It may not claim
    that the manual documents standard::content-type or
    standard::fast-content-type; those attribute names are GIO's, and the
    binding for the row is the owning package (pacman -Qo -> glib2 2.90.1-1).

D9  LANDING ORDER: A MINED ROW CITING corpus/knowledge/gio-content-type-file-r97.md
    RAISES CENSUS E11 UNTIL THAT FILE EXISTS.
