# ScoutOmarchyInput - how omarchy ships/changes input config (read-only)

Read-only; nothing run except cat/grep. Root: ~/.local/share/omarchy (OM). Reference tool: .ufo/waves/round-46/l1-draft/mado-devices.py (docstring + parse code).

## 1. What omarchy writes
Load order in ~/.config/hypr/hyprland.conf (lines 11, 17, 20): `source = OM/default/hypr/input.conf` (l.11) -> `source = ~/.config/hypr/input.conf` (l.17, user) -> `source = ~/.local/state/omarchy/toggles/hypr/*.conf` (l.20, glob).
- OM/default/hypr/input.conf:2-8: global `input { kb_layout = us, kb_variant =, kb_model =, kb_options = compose:caps, kb_rules = }`; `touchpad { natural_scroll = false }`. No `device {`, no `scroll_factor`.
- OM/config/hypr/input.conf (the template copied to ~/.config): `# kb_layout = us,dk,eu` (l.5), `# kb_variant = intl` (l.8) commented; `kb_options = compose:caps # ,grp:alts_toggle` (l.10); `touchpad { scroll_factor = 0.4 }` (l.33). Still no device block.
- OM/install/config/detect-keyboard-layout.sh (run by install/config/all.sh:12 and bin/omarchy-refresh-hyprland:11): reads /etc/vconsole.conf XKBLAYOUT/XKBVARIANT and `sed -i` INSERTS `  kb_layout = <x>` / `  kb_variant = <y>` before the `kb_options` line of ~/.config/hypr/input.conf. It inserts unconditionally, so a file that already has kb_layout gets a second line (last one wins in hyprlang, so DIFFER is not caused by this alone; the value is the last one).
- bin/omarchy-toggle-touchpad:24 and bin/omarchy-toggle-touchscreen:24 write `~/.local/state/omarchy/toggles/hypr/{touchpad,touchscreen}-disabled.conf` = `device {\n    name = <hyprctl-printed name>\n    enabled = false\n}` and also run `hyprctl keyword "device[<name>]:enabled" true|false` (l.16/22). This is the ONLY `device {` omarchy emits. Name comes from `hyprctl devices -j` (bin/omarchy-hw-touchpad:5: first .mice name matching /touchpad|trackpad/i; bin/omarchy-hw-touchscreen:5: first .touch/.tablets name). No `scroll_factor` and no kb_* key is ever written inside a device block anywhere in bin/ or migrations/ (grep of kb_layout|kb_options|kb_variant|scroll_factor|device { across bin, migrations, install, default, config: only the files above).
- Host state now: toggles/hypr holds only flags.conf and window-no-gaps.conf (no touchpad/touchscreen state file), consistent with "no device block".
- Migrations (330 files): only touch input.conf via sed on `windowrule = scrolltouchpad` (1758019332, 1767138576, 1771606249) and `(Alacritty|kitty)` -> `|foot` (1778008689). None touch kb_* or device. `devices -j` appears only in bin/omarchy-hw-touchpad and omarchy-hw-touchscreen.

## 2. Where the user's input.conf overrides omarchy
Host ~/.config/hypr/input.conf: `kb_layout = br` (overrides default us), `kb_options = compose:caps # ,grp:alts_toggle` (same value as default; trailing text after ` #` is a comment), `touchpad { scroll_factor = 0.4 }` (global input:touchpad:scroll_factor), repeat_rate/delay, numlock. kb_variant/kb_model/kb_rules inherit the default's empty values. So expected XKB = br / "" / compose:caps / "" / "" for every non-virtual keyboard: a tool fed both files (default first, user second) gets the same; fed only the user file gets the same too because the empty defaults equal the tool's own defaults. Feeding only the default file would give expected `us` -> DIFFER on all real keyboards (user override lost): the order and the user file matter.
Important for C1: `touchpad.scroll_factor` is NOT `device:scroll_factor`; the reference docstring (l.13) states the global/touchpad value never reaches the printed `scrollFactor`, so on this host every mouse expects -1.00. OM ships no device-scoped scroll_factor.

## 3. Omarchy commands that would make the C1 tool report DIFFER or STALE_BLOCK
(Reference verdict rules: mado-devices.py:72-90 - DIFFER = keyboard printed rules unequal to expected, FALLBACK, mouse scrollFactor unequal; STALE_BLOCK = a `device` block name not in any dump list; the toggle files are only seen if `--config` passes them, since the tool does not follow `source =`.)
STALE_BLOCK candidates (only if the state file is passed with --config):
1. `omarchy-toggle-touchpad off` / `omarchy-toggle-touchscreen off` persist `device { name = X; enabled = false }` in ~/.local/state/omarchy/toggles/hypr/ (survives reboots; removed only by the matching `on`). If device X is later absent (external USB touchpad/touchscreen unplugged, hardware change, renamed device, different name suffix `-N` ordering for duplicates) the block is NO_SUCH_DEVICE -> STALE_BLOCK (exit 4). The name written is the already-internal printed name, so on the same hardware it is MATCHED. Touchscreen blocks match only through dump lists `touch`/`tablets` (dump_names scans every top-level list, l.~320), so they MATCH correctly.
2. A user hand-written `device { name = ... }` in input.conf with a pretty/mixed-case name (names are case-sensitive, selftest "case-sensitive-name", l.510) - not omarchy-made, but omarchy docs (default/omarchy-skill) tell users to edit input.conf.
DIFFER candidates:
1. `omarchy-refresh-hyprland` / `omarchy-refresh-config hypr/input.conf` copy the template over ~/.config/hypr/input.conf (backup `.bak.<ts>`), then detect-keyboard-layout.sh re-inserts kb_layout from /etc/vconsole.conf. If vconsole XKBLAYOUT differs from the layout the compositor currently runs (compositor not reloaded; hyprland auto-reloads on save but a failing keymap is the other path) the file says X, the dump prints the old rules -> DIFFER; a vconsole layout that does not compile -> FALLBACK (us + empty).
2. Runtime-only: `hyprctl keyword input:kb_layout ...` / `hyprctl reload` paths used by omarchy do not change kb_* (reload is used by omarchy-hyprland-toggle:32, omarchy-restart-hyprctl:5, omarchy-update-git:17, monitor-internal scripts); a stale dump taken before a reload vs a newer file gives DIFFER. omarchy itself never sets kb_* at runtime (only `hyprctl keyword device[...]:enabled`, cursor:invisible, monitor, workspace, cursor:zoom_factor).
3. `omarchy-system-lock:16` `hyprctl switchxkblayout all 0` only resets the active group index: not part of the printed names (`rules/model/layout/variant/options`), so it NEVER yields DIFFER. Not a trigger.
4. `omarchy-toggle-touchpad` never changes scrollFactor (only `enabled`; `enabled` is not a tracked key - reference ignores other device keys), so it cannot make a mouse DIFFER.
Also NOT_COMPARED (exit 5, unsupported>0) risk: omarchy's input.conf contains no `$var`/`{{`/backslash; the touchpad state file has none either. Fine.

## 4. Net answer
Omarchy ships only global kb_*/touchpad settings plus ONE generated device-block kind (enabled=false toggle, state dir, globbed). The host currently yields OK in the L1 live run (9 AGREE, 1 VIRTUAL). Fixture ideas grounded in omarchy: (a) default+user two-file order (br overrides us), (b) detect-keyboard-layout duplicate kb_layout line (last wins), (c) toggle-touchpad state file naming an absent device -> STALE_BLOCK, (d) toggle-touchscreen block naming a `touch` list device -> MATCHED, (e) touchpad.scroll_factor=0.4 global -> mouse stays -1.00 AGREE.
Confidence: high on file contents/line numbers (read directly); medium on the "last kb_layout wins" claim (hyprlang behaviour inferred, not verified here) [INFERENCE].
