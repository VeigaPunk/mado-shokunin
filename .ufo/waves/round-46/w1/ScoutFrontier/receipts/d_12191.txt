Hello,
I am unable to dynamically toggle my touchpad using hyprctl keyword. The command fails with the error config option ... does not exist, even though the device is explicitly defined with an enabled state in my hyprland.conf.
This issue is reproducible with a minimal configuration and persists after full system reboots.
The Bug
A device block for elan1203:00-04f3:307a-touchpad is present in hyprland.conf.
Upon starting Hyprland, attempting to modify its enabled state via hyprctl fails.
Command executed:
$ hyprctl keyword "device:elan1203:00-04f3:307a-touchpad:enabled" false
Error received:
config option <device:elan1203:00-04f3:307a-touchpad:enabled> does not exist.
Key Observation
During troubleshooting, I noticed that hyprctl devices lists my touchpad under the mice: category. The Touch: category is empty. I am including this data point as it may be relevant to how Hyprland is processing the device's configuration.

elan1203:00-04f3:307a-touchpad

(empty)
Expected Behavior
The hyprctl keyword command should successfully modify the enabled state of the device as defined in the configuration.

Hello,
Thank you, @aphelei. Your suggestion was correct and solved the problem.
The issue was a syntax error on my end. I was incorrectly using colons to separate the device name from the parameter (device:name:parameter), instead of the correct device[name]:parameter format.
For anyone else facing this issue, the correct command to toggle the touchpad is:
# To disable
hyprctl keyword "device[elan1203:00-04f3:307a-touchpad]:enabled" false
# To enable
hyprctl keyword "device[elan1203:00-04f3:307a-touchpad]:enabled" true
I am closing this issue now. Thanks again for the help
