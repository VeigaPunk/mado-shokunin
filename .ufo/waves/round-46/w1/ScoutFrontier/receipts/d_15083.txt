So, in my setup I run a laptop with German keyboard layout and an external keyboard with ANSI layout connected via HP docking station.
The laptops' builtin keyboard should always use a German keymap, hence I set kb_layout = "de" in the global input config. Since the external keyboard has ANSI layout, I want its keymap the default to us. However, I frequently need to change that keymap (for writing mails .e.g.) to de. To enable this behaviour, set kb_layout = "us,de" in a device specific config and and added a key bind to toggle between layouts. This setup used to work perfectly fine until this morning when did a system update. After the reboot it is no longer possible to switch the keymaps with the defined bind. However, the keymaps are correctly configured, i.e., the buildin one is "de" the external is "us".
Manual invocation of the switch command (see below) on the command line returns "ok" but does not actually switch anything. The bind neither works on the external nor on the buildin keyboard. I checked the loaded config with "hyprctl devices". The devices list has many entries for below "Keyboards", two of which match may external keyboard: "keychron-keychron-k1-pro", and "keychron-keychron-k1-pro-keyboard". The config for the latter is correctly set to "us,de". I also tried using the first, but it does not change anything.
Setting kb_layout = "us,de" in the global input config does not help either, as well as setting the bind to another arbitray key. All other keybinds for as before. Any ideas?
hl.config({
input = {
kb_layout = "de",
kb_variant = "",
kb_model = "",
kb_options = "",
kb_rules = "",
follow_mouse = 1,
sensitivity = 0,
touchpad = {
natural_scroll = false,
},
},
})
hl.device({
name = "keychron-keychron-k1-pro",
kb_layout = "us,de",
sensitivity = 0
})
hl.bind(mainMod .. " + SHIFT + BACKSPACE", hl.dsp.exec_cmd("hyprctl switchxkblayout keychron-keychron-k1-pro-keyboard next"))

I finally found the root problem with this issue. On evey plug/unplug of the docking station the keyboard firmware seems to redecide through which devices it sends the real key strokes. I do not know if thats an issue with hyprland or rather keychron. However, here is workaround: you just have to bind the toggle key to both devices:
hl.bind(mainMod .. " + Y", hl.dsp.exec_cmd(
"hyprctl switchxkblayout keychron-keychron-k1-pro next; " ..
"hyprctl switchxkblayout keychron-keychron-k1-pro-keyboard next"
))
Is there something we can do in hyprland such that the kbd config survive USB-reenumeration?
