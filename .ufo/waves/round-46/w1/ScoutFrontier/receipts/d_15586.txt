Hyprland Version
0.56.0-1ppa1 (also reproduced on 0.55.2)
Description
Setting kb_variant inside a device { } block (targeting a specific
keyboard by name) causes that variant to be applied to all keyboard
devices, including unrelated virtual devices (video-bus,
power-button), not just the named device.
hyprctl getoption input:kb_variant correctly reports the empty/default
value from the general input { } block, confirming the general config
is parsed correctly. But hyprctl devices shows every keyboard's
active_keymap reflecting the device-scoped variant instead.
Config
input {
kb_layout = gb
kb_variant =
kb_options = ctrl:nocaps
}
device {
name = apple-inc.-magic-keyboard-with-touch-id-and-numeric-keypad-keyboard
kb_layout = gb
kb_variant = mac_fixed # custom variant in ~/.config/xkb/symbols/gb
kb_options = lv3:ralt_switch, ctrl:nocaps
}
Steps to reproduce
Set the config above (custom kb_variant valid and confirmed via
xkbcli compile-keymap --layout gb --variant mac_fixed)
hyprctl reload, then full logout/login, then full reboot — no change
hyprctl devices -j | jq '.keyboards[] | {name, active_keymap}'
Expected
Only the named device shows the custom variant; other keyboards use the
general input { } default (gb, no variant).
Actual
All keyboards, including virtual ones, show the device-scoped variant.
Additional testing done
hyprctl getoption input:kb_layout / input:kb_variant confirm the
general config is correct
hyprctl switchxkblayout <device> 0 has no effect
Reproduces from a raw TTY launch of Hyprland directly, bypassing any
session wrapper/display manager
Reproduces across a full reboot
