If you're using flakes, it's rather easy:
Make sure you have the hyprland flake input set to the PR you want to use (add the input if you don't already have it, update it otherwise):
{
inputs = {
# other inputs...
hyprland = {
# Set the URL the fork/branch you want to use to build
url = "github:vaxerski/Hyprland/scroll-factor";
# Use same input to avoid duplication of dependencies in nix store
inputs.nixpkgs.follows = "nixpkgs";
};
};
}
And then you'll find the package in inputs.hyprland.packages."${pkgs.system}".hyprland
If you want to install it on your nixos system, set the option programs.hyprland.package to the above:
programs.hyprland.package = inputs.hyprland.packages."${pkgs.system}".hyprland;
This will make your system grab the hyprland package from your flake input (which you can set to any version of hyprland) instead of the one from whatever nixpkgs version you're currently using
There may be better ways to do this, but at least I know this works, I've done this previously to build from a PR I submitted
Minimal working example:
{
inputs = {
nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
hyprland = {
url = "github:vaxerski/Hyprland/scroll-factor";
inputs.nixpkgs.follows = "nixpkgs";
};
};
outputs = inputs: let
system = "x86_64-linux"; # change if you're on some other system
in {
nixosConfigurations.nixos = inputs.nixpkgs.lib.nixosSystem {
inherit system;
specialArgs = { inherit inputs; }; # Pass flake inputs to modules
modules = [
# This or whatever you have your configuration in
./configuration.nix
# Then add the following to your configuration.nix (or leave it here, should work too)
({ pkgs, inputs, ... }: {
programs.hyprland.package = inputs.hyprland.packages."${pkgs.system}".hyprland;
})
];
};
};
}

i'm pretty sure package = hyprland.packages.${pkgs.stdenv.hostPlatform.system}.hyprland;
changes that pkg to the compiled one, no? @fufexan
To my understanding, it wouldn't. (perhaps you're thinking of overlays? I think overlays do that, not sure)
Setting the NixOS option programs.hyprland.package does not change any entry in pkgs, so pkgs.hyprland still points to whatever the version of Hyprland is in your nixkpgs channel.
Setting the option simply assigns to config.programs.hyprland.package (config contains the "result" of your defined options, with all your modules merged together), which, by default, is set to pkgs.hyprland
Generally, setting programs.hyprland.enable = true should make it available to all display managers, passing them the proper package (config.programs.hyprland.package). In your case, you're defining your greetd entry by hand, which intuitively I would not think to be necessary, but idk. Anyway, I'm almost certain that if you configure greetd to run pkgs.hyprland, it will indeed run hyprland from nixpkgs, and not the one you configured in any other modules.
So you could simply change your entry to use config.programs.hyprland.package instead of pkgs.hyprland
By the way, this would explain why your hyprland --version outputs Hyprland 0.50.0 built from branch at commit dirty ().: your programs.hyprland.package is exposed to your system environment, so you can see it's available, but I would bet hyprctl version reports a different version (because it queries the running instance for its version, and I'm convinced your running instance is from nixpkgs)
