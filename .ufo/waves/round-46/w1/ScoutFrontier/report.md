## Leads for the build and attack seats (derived from the opened material; not claims)
1. **uinput remappers are ordinary keyboards** (B4 kanata, B5 keyd): a tool that treats every `*virtual*` name as VIRTUAL
   would misreport `keyd-virtual-keyboard`; contract: only the `hl-virtual-keyboard` prefix (S323 pin) is VIRTUAL. A
   fixture with a `kanata`/`keyd-virtual-keyboard` keyboard whose rules equal the global layout should be AGREE, and one
   with differing active index but equal rules is also AGREE (the contract compares rules, not `active_layout_index`).
2. **FALLBACK cases are real and recurring** (A5, A6): printed `us` with empty variant for a configured non-us
   layout. The 0.55.4 report prints `layout: us` with `variant: gallium` in the error, while the device would print `us`/empty.
3. **Multiple nodes per physical keyboard** (B3) and **renaming nodes** (B2): per-node rows, exact-name block matching
   (case-exact, as `case-exact-dump-name` already separates).
4. **Two scroll-factor ranges**: global `input:scroll_factor` `.max = 2` (`Hyprland-ConfigValues.cpp:296`) versus the
   per-device clamp 0..100 (A2). A block `scroll_factor = 150` must expect 100, and the global option must **not** change
   the expected per-mouse `-1`.
5. **R1 is an unconfirmed counter-claim** to the contract's "device value applies only to the named device"; keep it as
   an attack seed against the pinned code path, not as evidence either way.
6. Host observation (shape only): `receipts/live-devices-host-l1.txt:14` prints the fcitx5 virtual keyboard with its own
   layout and options (not the global ones), i.e. VIRTUAL, matching S322/S323 and B5's mechanism class, not B5's "stays us".
