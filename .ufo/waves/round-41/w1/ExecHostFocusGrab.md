# ExecHostFocusGrab — report (round 41 w1)

**Target:** which software on this host can bind the focus-grab protocol.

**Answer:** only the compositor, and only as the **server**. Nothing installed on this host holds
`hyprland_focus_grab_manager_v1` / `hyprland_focus_grab_v1` on the client side.

Seat deliverable: `.ufo/waves/round-41/w1/ExecHostFocusGrab/finding.md` (full evidence, commands, hashes).

## Method and coverage

Pattern `hyprland_focus_grab_manager_v1|hyprland_focus_grab_v1|hyprland_focus_grab|focus-grab|focus_grab`, `grep -r -l -a -E`.
Trees swept: `/usr/bin` (3369 files), `/usr/lib` (122032), `/usr/lib64` (symlink → `/usr/lib`), `/usr/share` (191593),
`/usr/include` (39347), `/usr/local`, `/opt` (1579, incl. root-only `/opt/containerd` closed with read-only `sudo -n`,
`GREP_EXIT=1`), `~/.local/bin` (49), `~/.local/lib` (2677), `~/.local/share` (116131), `/usr/src`, `/usr/lib32`.
`/usr/libexec` and `/usr/libdata` do not exist.

**Method positive control:** the same pattern matches the L1's fetched client source
(`fetch/quickshell-grab.cpp:11,98`, 2 hits) — a client would have been found had one been installed.

## Results

**1. `/usr/bin/Hyprland`** (16 099 784 B, sha256 `55da553be71222566ee73b973d2f56dbb9939044d8f22f81aa54b66c83f2f6d1`) —
the only binary holding the protocol. Two occurrences each of `hyprland_focus_grab_manager_v1` and `hyprland_focus_grab_v1`;
`strings` also shows `hyprland_focus_grab_manager_v1_interface` (:6348), `hyprland_focus_grab_v1_interface` (:13442), and the
generated member names `cleared`, `add_surface`, `remove_surface`, `create_grab`. That is a compiled **server**
implementation.

**2. Server-side headers only** — `/usr/include/hyprland/protocols/hyprland-focus-grab-v1.hpp` (226 lines, generated by
hyprwayland-scanner 0.4.6; declares `hyprland_focus_grab_manager_v1_interface` at :58, `hyprland_focus_grab_v1_interface`
at :59, operates on `wl_resource`) and `/usr/include/hyprland/src/protocols/FocusGrab.hpp`
(`class CFocusGrabProtocol : public IWaylandProtocol`, `CFocusGrab::finish(bool sendCleared)`).
`grep -c 'wl_proxy|wl_registry_bind'` on the generated header = **0** → no client-side binding code on disk.
Ownership is by path (`/usr/share/licenses/hyprland` present) — `pacman -Qo` is forbidden for this seat, marked `[INFERENCE]`.

**3. Advertisement is logged, not bound.** `fetch/xdph-journal.txt` (sha256 `bf8fa91a…600aaf7`, 153 lines, re-verified) line 117:
`Got interface: hyprland_focus_grab_manager_v1 (ver 1)` at `2026-10-25T13:36:24-03:00` from pid 1952.
`/usr/lib/xdg-desktop-portal-hyprland` (762 024 B, sha256 `8ac95938…35bd1bf`, v1.4.1) holds **no** focus-grab string; its
`hyprland_*` strings cover only global_shortcuts, input_capture, toplevel_export, toplevel_mapping. The portal enumerates
the global and does not bind it.

**4. No running process is a client.** All 809 distinct files mapped by any process were tested. Two hits:
`/usr/bin/Hyprland` (pid 1632, `Hyprland --watchdog-fd 4`) and the user journal (pid 1829,
`journalctl --output=short-iso -b -p 3 -n0 -f` — a log follower mapping data, not code). walker (1820) and
swayosd-server (1825) map only `libgtk-4` (false positive below); xdph (1952) maps only itself; mako (1681),
waybar (1683), xdg-desktop-portal (1859), xdg-desktop-portal-gtk (1894) hold no match.

**5. False positive, excluded.** `focus_grab` matched `libgtk-4.so.1.2400.1:45425` — the GTK widget API name
`gtk_window_set_pointer_focus_grab` inside a contiguous `gtk_window_*` name block. Not exported
(`nm -D | grep -c pointer_focus` = 0), not in `/usr/include/gtk-4.0`, and GTK4 holds no `hyprland_*` string at all.
`/usr/bin/gtk4-rendernode-tool` carries the same block and does not even link libgtk-4 (`NEEDED` = `libgdk_pixbuf-2.0.so.0`).

**6. Honest negatives.** No quickshell/qs installed (`find … -iname '*quickshell*'` empty — the reference client is a
fetched source, not host software); no vicinae, fuzzel, wofi, rofi, wtype, ydotool, kitty, foot, ghostty, wezterm,
wl-screenrec, wf-recorder, swayidle, hyprpm; no libqt6waylandclient; `libgtk-layer-shell.so.0.10.1` present but no match;
no second compositor (only `Hyprland` + `Xwayland`); `wayland-info` exists but has **0** `hyprland_` strings, so it can print
the registry name at runtime and cannot `wl_registry_bind` the manager; `hyprctl` speaks the compositor IPC socket, not this
protocol; walker, waybar, mako, makoctl, hyprlock, hypridle, swaybg, grim, slurp, wl-copy, wl-paste, alacritty all checked
by `readlink -f` path and hold nothing.

## Interpretation (stated in the finding)

Holding the string is evidence of **capability**, not of use: `/usr/bin/Hyprland` proves the compositor can serve the
protocol, and `fetch/xdph-journal.txt:117` proves it did advertise it on 2026-10-25 — neither proves any client bound it,
and this census says none on the host can. Conversely, absence of the string is strong (not absolute) evidence that a
binary cannot bind the manager, since generated Wayland bindings are not built from runtime strings.

## Limits

Mapped-file granularity only (anonymous memfd/JIT regions uninspectable); `/proc/*/maps` of other uids unreadable (uid 1000
session fully covered); no live probe — this seat may not open a Wayland connection, so "bindable" is inferred from compiled
code, not exercised.

## Safety

Read-only throughout. No compositor or Wayland connection, no input injection, no package transaction (pacman untouched), no
git/jj mutation. Only `journalctl`-adjacent action was grepping the frozen journal receipt; the one privileged read was
`sudo -n grep` over the root-only `/opt/containerd` (read-only, no hits). No tools installed, no versions changed.
Scratch files kept in `/tmp` (`mapped.txt`, `scan_err.txt`, `containerd_hits.txt`).
