## Verdict

The claim **holds for the tool's own syscalls in all four scenarios**: exactly one `execve`
(`/usr/bin/python3`), zero `clone`/`fork`/`vfork`, zero socket/connect syscalls, zero
open-for-write/create/truncate, zero mutating-fs syscalls; the only `write(2)` is the tool's own
`write(1)` of its output. One landed **data defect** was found in the PROVINCE restatement
(F3: "`--selftest` opens no file" is false — it opens three paths), one w1 tool defect is confirmed
and **broadened** (F4: closed stdin crashes *every* mode, not only `--clients -`), and three bounded
caveats are reported (F5 invocation isolation, F6 interpreter trust root, F7 open-before-check).
The live host receipt reproduces exactly (F2).

## F3 — DEFECT (landed data, low): PROVINCE.md:32 says `--selftest` "opens no file"; it opens three

`PROVINCE.md:32` (data commit) records for this tool: "`--selftest` opens no file and writes nothing
(its cases are in-memory strings; `grep -n 'mkfifo\|O_WRONLY\|O_CREAT' tools/mado-geometry.py`
finds none)". The grep clause supports "writes nothing" only. The selftest's negative
`read_regular` cases (`tools/mado-geometry.py:353-358`) call `read_regular("/nonexistent/none")`,
`read_regular("/")` and `read_regular("/dev/null")`, so the run opens all three paths
(`tr-devnull-fd.log`):

```
openat(AT_FDCWD, "/nonexistent/none", O_RDONLY|O_NONBLOCK|O_CLOEXEC) = -1 ENOENT (No such file or directory)
openat(AT_FDCWD, "/", O_RDONLY|O_NONBLOCK|O_CLOEXEC) = 3
fstat(3, {st_mode=S_IFDIR|0555, st_size=158, ...}) = 0
openat(AT_FDCWD, "/dev/null", O_RDONLY|O_NONBLOCK|O_CLOEXEC) = 3
fstat(3, {st_mode=S_IFCHR|0666, st_rdev=makedev(0x1, 0x3), ...}) = 0
```

None is read (no `read(3` on any of the three; each is rejected by the regular-file check and
closed). Impact: a prose overstatement in the province's evidence column — exactly the class of
defect the province exists to prevent ([OBS] cell asserting an unobserved fact). Attack: the row
claims a syscall-level fact its own cited grep cannot show. Smallest remediation: replace "opens no
file" with "opens no caller-supplied file (only `/nonexistent/none`, `/` and `/dev/null` to exercise
the rejection path) and writes nothing"; the tool bytes need no change.

## F4 — DEFECT (tool, low-medium; w1 `RevRefTool` V5 still holds, broadened)

w1 V5 recorded `--clients -` with fd 0 closed: `AttributeError` at `tools/mado-geometry.py:410`,
exit 1, no SETUP line. At the data commit the same bytes still fail, and the defect is **wider than
recorded**: `main()` evaluates `sys.stdin.buffer` before dispatch, so *every* mode crashes when fd 0
is closed at exec, including `--selftest`, which reads no stdin:

`err-selftest-closedstdin.txt` (fd 0 closed, `--selftest`):

```
File "/fast/scratch/hyaku/mado-r43/SentLiveRun/mado-geometry.py", line 410, in main
    return run(sys.argv[1:], sys.stdin.buffer)
                             ^^^^^^^^^^^^^^^^
AttributeError: 'NoneType' object has no attribute 'buffer'
```

`--clients /dev/stdin` with fd 0 closed crashes identically before argument parsing. `--clients -`
with fd 0 closed: same, stdout empty, stderr 405 B, exit 1 (`tr-stdin-closed3.log`,
`err-stdin-closed3.txt`). Contract divergence: the docstring's setup failures are `usage |
unreadable | too_large | bad_json`, stdout exactly one `MADO_GEOMETRY: SETUP <reason>` line, exit 2;
this path yields a traceback and exit 1, and `--selftest` cannot fail for a reason the contract
names. Smallest remediation: guard the dispatch — pass `sys.stdin.buffer if sys.stdin is not None
else None`, and let mode `run` with `clients == "-"` raise `Setup("unreadable")` when it is `None`;
then `--selftest` works with fd 0 closed and `--clients -` gets the contract's SETUP line. The C1
counter never exercises this (it runs `py + "-I"` with stdin supplied, `quality/counters/
c1-r42-geometry.py:205,435`), so the 37/37 does not cover it.

## F5 — CAVEAT (invocation, low): the documented host command is not import-isolated

Every scored/live invocation uses `python3 -I` (counter `:205,:435`; receipt line). The documented
host command does not: `SKILL.md:225` reads
`hyprctl clients -j | python3 tools/mado-geometry.py --clients - --rules ~/.config/hypr/gkeep.conf`
(also `:158`, `:248`, `:251`, `:281`, `:294`), and the docstring's own usage line
`tools/mado-geometry.py:10` runs the shebang `#!/usr/bin/env python3`. Without `-I`, `sys.path[0]`
is the script's directory, so a module named like a stdlib import in `tools/` runs before the
tool's logic. Measured in scratch (`shadow-demo/`, a copy of the tool beside a `json.py` that writes
a marker and prints `SHADOW_JSON_EXECUTED`):

- `python3 -I tool.py --selftest` → `MADO_GEOMETRY_SELFTEST: 73/73 passed`, exit 0, `json.py`
  never imported, no marker file (`out-shadow-I.txt`, `err-shadow-I.txt`).
- `python3 tool.py --selftest` (same directory, no `-I`) → `SHADOW_JSON_EXECUTED` on stderr, the
  marker file created, then `AttributeError: module 'json' has no attribute 'dumps'`, exit 1
  (`err-shadow-noI.txt`, `shadow-demo/MARKER-written`).

So "writes nothing / starts no process / opens no socket" is a property of the tool's code **under
`-I`** (and of the recorded runs); the un-isolated form executes whatever `tools/{json,re,stat,
sys,os}.py` contains, with the operator's privileges. Attack requires write access to `tools/`
(contributor or unpacked archive), so impact is bounded; remediation is one word: document and use
`python3 -I tools/mado-geometry.py` in `SKILL.md` and in the docstring usage lines. This does not
falsify the claim for the receipt that C1 cites.

## F6 — NOTE (trust root): `-I` still executes system site-packages code

Even isolated, the interpreter reads `/usr/lib/python3.14/site-packages/distutils-precedence.pth`
and imports `_distutils_hack` from site-packages before the tool runs (`tr-hostpipe.log:78-100`):

```
openat(AT_FDCWD, "/usr/lib/python3.14/site-packages/distutils-precedence.pth", O_RDONLY|O_CLOEXEC) = 3
openat(AT_FDCWD, "/usr/lib/python3.14/site-packages/_distutils_hack/__init__.py", O_RDONLY|O_CLOEXEC) = 3
```

That code starts no process, opens no socket and writes nothing here, so it does not break the
claim; it does mean the run's trust root is "tool file + Python stdlib + `/usr/lib/python3.14/
site-packages` (root-owned)", not "tool file + stdlib". `-I` stops user site (`~/.local`) and
`PYTHON*` env, not system site hooks. Informational for the L1; no action proposed.

## F7 — NOTE (open-before-check, low): non-regular paths are opened, then rejected

`read_regular` (`tools/mado-geometry.py:90-104`) opens first and classifies with `fstat` after. For
`--rules /dev/ptmx` the open **succeeds** and allocates a pty master before the mode check rejects
it (`tr-ptmx-fd.log`:319-321):

```
openat(AT_FDCWD, "/dev/ptmx", O_RDONLY|O_NONBLOCK|O_CLOEXEC) = 3
fstat(3, {st_mode=S_IFCHR|0666, st_rdev=makedev(0x5, 0x2), ...}) = 0
close(3)                        = 0
```

No read follows; stdout is `MADO_GEOMETRY: SETUP unreadable`, exit 2. The claim's literal three
verbs still hold (no process, no socket, no write). The residual is that a caller-chosen device
path is opened once, and the open uses neither `O_NOCTTY` nor `O_NOFOLLOW`: a device whose open has
side effects is touched. `/dev/watchdog` is the named class — opening it arms a reboot timer unless
closed with the magic character, so an operator who passes it as `--rules` can reboot the host
[INFERENCE: kernel watchdog semantics; NOT tested, no such device opened by this seat]. Smallest
remediation: classify before opening (`os.stat(path).st_mode` regular, then open, then re-`fstat`
and compare `st_dev/st_ino`) and add `O_NOCTTY|O_NOFOLLOW` to the open flags. Severity low: the
path is operator-supplied, and the tool's documented inputs are config files.
