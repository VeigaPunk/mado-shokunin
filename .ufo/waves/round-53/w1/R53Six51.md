## One bounded move

Adopt a **single append-only evidence receipt schema with separate claim-specific records**, requiring each record to name exact input artifact path and digest, counter path and digest, revision, command/exit/output, and named expected predicate/control. For C1, receipt must separately show production ledger and each no-work/forgery control; for C2, receipt must separately bind old/corrected entry and opened pin-root identity. The shared schema improves operability through replayable, artifact-specific receipts and coverage through explicit proposition/pin inputs, while the separate records preserve causal separation and prevent one claim's green result laundering the other. No counter or claim predicate is changed by this move.

## Contradictions and risks

- Frozen claims say C1/C2 are causally separate; a shared receipt format is a shared process surface. If that phrase bars shared evidence infrastructure, use the same fields in independent receipts and do not share a writer or verdict path. Interpretation remains unresolved.
- Hashes establish identity, not correct population, parser behavior, proposition entailment, source truth, or load-bearing controls.
- A receipt can faithfully memorialize a defective counter or false quote. Independent C2 source review remains required; C1 remains explicitly structural, not semantic.
- Receipt generation must happen only after exact artifact bytes and expected results are frozen, or it can track drafts while silently missing the final artifact, repeating r52's identity/provenance failure.
