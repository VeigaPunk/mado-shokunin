## Summary of findings

1. **One real disagreement the C2 model does not declare**: the canonical (symlink-target) watch. The C2 model prints `path=<realpath>`; Hyprland's code watches the realpath (`ConfigWatcher.cpp:69`) but records the **symlink path** as the watch's `.file` (`:70`), and that `.file` is what the event callback and the reload log (`legacy:1079-1080`, K17/K18) report. Agreement on what the kernel watches; disagreement on the name that reaches the callback and log.
2. **C2 declared divergence #3 (GLOB_TILDE `~user`) is unreachable in Hyprland as stated.** `absolutePath` (`MiscFunctions.cpp:10-12`) rewrites a leading `~` before `glob` sees the string, so GLOB_TILDE never expands a leading tilde on that path. The declared divergence is misstated (no behaviour difference for leading `~`; `~user` produces the same concatenated string in both models).
3. **`~` is sourced differently**: Hyprland reads `getenv("HOME")` (K25, `MiscFunctions.cpp:65`); the C2 model takes `--home` and marks `~` without `--home` as `unsupported`. Equal only when `--home` equals `$HOME`. This is not among the five declared divergences.
4. **Main-config-first is pinned but uncited.** `legacy:776` (K20) clears `m_configPaths`; `legacy:779` re-inserts the main config. No K row cites `:779`; the C2 rule "`--config` is always the first list entry" therefore has no C1 row behind it.
5. **Several C2 rules have pinned code with no K row** (error branches, bogus, nomatch, nonregular, `..`/`./`): the C1 entry can cite them only by adding rows (frozen) or must state them as unquoted.
6. **Facts the C2 model counts or labels but the chain does not explain**: missing paths produce a watch line whose `inotify_add_watch` return is never checked (wd=-1, no event); a symlinked primary watch sits on the link inode (K30) and is inert for writes through the target; duplicate paths alias to one kernel watch (man7 pin, mask replaced).
7. **C3 interplay**: C3's `SRC` window is the first 15 lines; C1's `prov` window is 30 lines. Base entries are all within 15 (50/50 with a `source:` line), so C3 is unbroken at base, but C1 is allowed to place `source:` at lines 16-30, which would silently exempt those ids from C3's `dangling` count. Authoring constraint needed.
8. **No C3 definition is broken by the S383-S390 rows themselves**: 11 cells each (draft and base), and every new id is cited by a K row, so the `used-by` names C1 must write coincide with the back-references C3 requires. S-ids inside fences or HTML comments: none at base.
