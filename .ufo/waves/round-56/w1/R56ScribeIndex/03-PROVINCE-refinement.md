## 3a. Refinement paragraph (append after the Round-55 refinement, end of file, append-only; same form as the round-36 and round-55 refinements)

**Round-56 refinement (append-only; one read-only tool, three record instruments, one knowledge entry; no new write surface):** `tools/mado-watchplan.py` is a read-only join. It reads only the files its caller names: `--config` (the main Hyprland config, a regular file), at most one `--getoption` file (a captured `hyprctl getoption misc:disable_autoreload -j` reply, 1 MiB cap), and the files that the config's `source =` lines reach (absolute, `~` with `--home`, relative and glob forms); on those paths it calls only `stat`, `lstat`, `realpath`, `glob` and the `isdir`, `lexists` and `islink` checks. From these it predicts the inotify watch list Hyprland 0.56.2 registers for the config tree and reads `misc:disable_autoreload` the way hyprlang does. Constructs outside its model are counted `unsupported` and never guessed. It starts no process, opens no socket and writes nothing; the operator captures the `getoption` reply with the read verb and applies no change. Its capability row enters SCORECARD only on the round's C2 `TARGET_MET`. The record instruments are `quality/counters/c1-r56-autoreload-entry.py` (the entry's counter), `quality/counters/c3-r56-used-by.py` (the registry used-by counter) and `quality/check-r56-controls.py` (the independent harness). The two counters read git objects only, at the revision they are given, and write nothing. The harness also reads git objects, but it builds scratch repositories, exports the tool and its fixtures and runs them and the counters as child processes, writing only under its `--work` directory; it never writes the lane or the fleet repo. None of them touches a config plane, the compositor, a socket or a host service. Reload, inotify delivery and the Lua config provider stay outside every instrument.
