## Criterion from the round-55 scope mistake (round 56; M56-1, mined from round 55; draft, not landed)

**107.** **A registry row cited by an entry's evidence row has an anchor that names the row's own source file and covers the quoted line (extends 77 and 97)** — For every evidence row of a knowledge entry (a table row whose third cell is a registry id `S###` and whose fourth cell is `<file>:<N>`, the K-row and E-row grammar of `corpus/knowledge/`, any row class), the registry row of that id in `corpus/SOURCES.md` must satisfy: NAME, the last path component of the last `http(s)://` token of the registry row's source cell (the upstream file the row credits), occurs in the anchor cell (cell 6) as `NAME:` not preceded by an identifier character, followed by a comma-separated list of locators whose first item is `N` or `N-M` (later items continue the list only while they begin with digits); and some range in that list includes `N`, the quoted line. A row whose registry anchor names no such file, or whose ranges all exclude `N`, is a violation whatever its quote or proposition says. The fix is a supersession row with a widened anchor (registry rows are append-only, CORPUS rule 2) or a re-cite of a row whose anchor covers the line; each such change is logged in the round lesson. Check: `python3 -I quality/check-anchor-cover.py --repo . --rev <rev> --entry corpus/knowledge/<entry>.md --work <scratch>` prints one `ANCHOR_COVER: row=<id> sid=<S###> line=<N> name=<NAME> locators=<list> verdict=OK|MISS [reason=no-name|no-cover]` line per evidence row, then `CHECK107: rows=<n> covered=<k> miss=<m> verdict=OK|FAIL`; the requirement is `miss=0` with `rows>0`; exit 0 on OK, 1 on FAIL, 2 on setup error (stdout empty). The instrument reads git objects at `<rev>` only and writes only under `--work`. Shown able to fail: the committed round-55 entry `corpus/knowledge/hyprland-keyboard-repeat-numlock-r55.md` at `63f48dc1` reads `rows=32 covered=25 miss=7 verdict=FAIL`, rc 1 (`receipts/anchor-cover-r55-63f48dc1.out`): K14 (S318 anchor `ConfigValues.cpp:271-279,296` against line 280), K17 (S052 anchor names no `wayland.xml:`, line 2741), and five E-rows the frozen r56 K-only leg never sees: E04 (S052, 2732), E05 (S052, 2740), E11 (S052, 2740), E08 (S316, anchor `1213-1295,1350-1383,2119-2131` against 1195), E14 (S379 `Seat.cpp:441-448,603-609` against 350). The same entry against a scratch registry in which the anchors are widened to name and cover every quoted line reads `rows=32 covered=32 miss=0 verdict=OK`, rc 0 (`receipts/anchor-cover-variant-positive.out`); the same scratch registry with S318 shrunk to `271-278` reads `covered=30 miss=2` (K13, K14), rc 1 (`receipts/anchor-cover-variant-negative.out`). (lesson: lessons/round-56.md#mistakes M56-1; extends 77 and 97; round-55 K14/K17 replay in `.ufo/waves/round-56/receipts/scope-replay-r55.txt`)
Declared limit: the check reads the anchor text, not the upstream file, so an anchor that names the right file and a range whose lines carry a different statement passes (the sentence-to-pin audit of criterion 104 carries that); a source URL whose last component is not the file the anchor names (a rename, or a directory-qualified name such as `legacy/ConfigManager.cpp` cited as `ConfigManager.cpp`) reads MISS and must be read before it is treated as a violation; an entry with no evidence rows reads `rows=0 verdict=FAIL`, so an empty entry is not vacuously green.
