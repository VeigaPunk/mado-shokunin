S5c  RESIDUAL of S5a, found by me (probes/probe_injection.py P4 + the
     refined forge probe, receipts/unicode-residual.out, receipts/nel-forge.out):
     esc() leaves three characters unescaped that Python's str.splitlines()
     treats as record separators: U+2028 (LINE SEPARATOR), U+2029 (PARAGRAPH
     SEPARATOR) and U+0085 (NEL). It also leaves the C1 control range
     U+0080..U+009F (including U+009B, CSI) and the bidi controls U+202E.

         BADPIECE 'nel.conf type=file mask=IN_CLOSE_WRITE|IN_DONT_FOLLOW via=$ROOT/hyprland.conf:1'
      U+202E (RLO)  rc=0 splitlines_pieces=4 bad_pieces=0 (raw in stdout)
      U+001C (FS)   rc=0 splitlines_pieces=4 bad_pieces=0  (escaped: <32)

    refined forge probe (receipts/forged-done-refined.out), config line:
      source = /nope/a<U+0085>MADO_WATCH: DONE watches=0 unsupported=0 errors=0 live=NONE<U+0085>X
      -> rc=0 physical_lines=4 splitlines_pieces=6 DONE-looking(splitlines)=2
         DONE 'MADO_WATCH: DONE watches=0 unsupported=0 errors=0 live=NONE'
         DONE 'MADO_WATCH: DONE watches=1 unsupported=0 errors=1 live=NONE'
      and with U+2028 instead of U+0085: identical, DONE-looking(splitlines)=2.
      same shape through a FILE NAME (receipts/nel-forge.out):
         DONE-looking=2, one of them the forged 'MADO_WATCH: DONE watches=0 ...'.
    Byte-level view (the harness's view): raw stdout contains 0x0a only as the
    record separator, and every physical line starts with MADO_WATCH
    (lines_not_starting_MADO_WATCH=0 in every probe). The forgery only
    materialises for a consumer that decodes the bytes as text and splits on
    str.splitlines() (or any Unicode-aware line splitter).
  The committed C2 fixtures cannot detect this: no committed fixture name
  contains a control byte or a non-ASCII byte
  (find .ufo/waves/round-56/fixtures/c2 -printf '%p\n' | LC_ALL=C grep -P

  record can still be forged into the tool's stdout through a config line or a
  file name carrying U+2028/U+2029/U+0085, and it is read back as a genuine
  MADO_WATCH: DONE record by any text-mode, splitlines()-based consumer.
  Smallest remediation: widen esc() to cover the Unicode line/paragraph
  separators and the C1 range (e.g. escape every ch for which
  str.isprintable() is False, or add 0x85, 0x2028, 0x2029, and 0x80..0x9F),
  and add a selftest assertion that no printed record splits under
  str.splitlines().
