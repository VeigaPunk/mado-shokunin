## Top 3 lessons / gains

### 1. A new operability tool for the live desktop: who is reading Hyprland's event socket (round 37)

`tools/mado-eventq.py` is a read-only census of socket2 subscribers. It never connects to the socket; it reads the kernel unix-socket table, the two exact failure markers from Hyprland v0.56.2 `EventManager.cpp` (`:175` queue overflow at `MAX_QUEUED_EVENTS = 64`, `:155` write failure), and `debug:disable_logs`. The live receipt on João's machine found two subscribers (waybar and a socat process), zero markers, and `markers_observable=no`, and an independent `/proc` census agreed on the same two server inodes. This is the first new runnable tool since `mado-wsrules.py` in round 27, and the first that inspects running state rather than config bytes. It answers a real question for an Omarchy bar: whether a slow bar module can be silently dropped by the compositor.

### 2. "Zero errors logged" is not "zero errors" when logging is off (round 37 rejects, M37 lessons)

Two staged entries (`event-queue-host-measurement-r28.md`, `event-queue-journal-measurement-r29.md`) claimed the event queue had never overflowed on the host. The lane refused both: `debug:disable_logs` defaults to true and reads 1 on the host, the core logger returns before formatting (Logger.cpp `:15-16`, `:47-48`), and the unit journal never carries core lines (probe: 7 log hits vs 0 journal hits). So the zero was a null channel. The tool encodes the same rule as `markers_observable`. This is the most transferable desktop lesson of the window: before trusting an absence in a log, confirm the log could have recorded the event.
