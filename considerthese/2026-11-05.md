### 1. Round 87 moves the lane onto the notification plane: a read-only mako resolver, with a result that did not pass its own bar

`tools/mado-mako.py` (new in `7563452f`, measured at `00c96721`) takes a mako config, an app name, an urgency and a set of active modes, and prints the effective value of each style option for one notification, following the `include=` chain and criteria sections (`[app-name=…]`, `[urgency=…]`, `[mode=…]`, combined). The companion note `corpus/knowledge/mako-criteria-resolution-r87.md` ties each rule to a line of the installed mako 1.11.0 manual (registry row S493, container sha256 `17ffc88c…`, decompressed text `f717848f…`): AND across fields (lines 431-433), last definition wins per option (435-437), mode gate (469-470), initial mode `default` (620), no spaces around `=` (507). It refuses rather than guesses: a relative `include=`, an include cycle, `summary` together with `summary~`, bare boolean tokens, and a mid-line `#` is left UNSTATED rather than treated as a comment. It also records João's actual chain: `~/.config/mako/config` is a symlink into the Omarchy theme `mako.ini`, which includes `core.ini` (top-right, 5000 ms timeout, width 420, and `[mode=do-not-disturb] invisible=true`, `[urgency=critical] default-timeout=0 layer=overlay`, and an `[app-name=Spotify] invisible=1` rule).

The result is not a clean win, and the lane says so. The non-author verifier (`round-87-verifier-spotcheck.md`) re-ran the counter and reproduced the same line, and marked the coverage axis **unchanged**, not improved.
